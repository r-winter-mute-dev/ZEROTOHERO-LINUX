Seit gestern zeigt der Browser auf werkstatt eine alte Testseite statt www.example.org. Auf Lenas Rechner geht es. **Deine Mission: Frag DNS gezielt ab, verstehe, in welcher Reihenfolge Linux Namen auflöst, und finde den Fehler.** Lernziel 109.4.

## Fragen an DNS

<Karte nr={1} titel="host und dig">
**DNS** ordnet Namen Daten zu, in **Records** verschiedener Typen:

| Typ | Inhalt | Beispiel |
|---|---|---|
| A | IPv4-Adresse | www.example.org → 203.0.113.80 |
| AAAA | IPv6-Adresse | www.example.org → 2001:db8:80::80 |
| MX | Mailserver mit Priorität | example.org → 10 mail.example.org |
| NS | zuständiger Nameserver | example.org → ns1.example.org |
| CNAME | Alias auf einen anderen Namen | web.example.org → www.example.org |
| PTR | Rückwärts: Adresse → Name | 80.113.0.203.in-addr.arpa → www.example.org |

Zwei Werkzeuge fragen DNS direkt:

- **host** antwortet knapp. `host www.example.org` zeigt A, AAAA und MX. `host -t MX example.org` fragt nur einen Typ. `host 203.0.113.80` fragt rückwärts. Mit einem zweiten Argument fragst du einen bestimmten Server: `host www.example.org 203.0.113.53`.
- **dig** zeigt die ganze Antwort: Status (`NOERROR`, `NXDOMAIN` für „gibt es nicht“), Fragen- und Antwortteil mit TTL, und unten den Server, der geantwortet hat. `dig example.org MX` fragt einen Typ, `dig @203.0.113.53 www.example.org` einen bestimmten Server, `dig +short …` gibt nur die Werte aus, `dig -x 203.0.113.80` fragt rückwärts.

**Wichtig:** host und dig fragen **nur DNS**. /etc/hosts kennen sie nicht. Welche Server sie fragen, steht in **/etc/resolv.conf**.
</Karte>

<Merke>host kurz, dig ausführlich. dig NAME TYP, dig @SERVER NAME, dig +short, dig -x IP, host -t TYP NAME. A, AAAA, MX, NS, CNAME, PTR. Beide fragen nur DNS, nicht /etc/hosts. NXDOMAIN: Name existiert nicht.</Merke>

## Die Reihenfolge

<Karte nr={2} titel="nsswitch.conf, /etc/hosts und systemd-resolved">
Normale Programme wie ping, ssh oder der Browser fragen nicht selbst DNS. Sie rufen die C-Bibliothek, und die schaut in **/etc/nsswitch.conf** nach, wo sie suchen soll:

```
hosts:          files mdns4_minimal [NOTFOUND=return] dns myhostname
```

`files` heißt /etc/hosts, `dns` die Server aus /etc/resolv.conf, `mdns4_minimal` Namen auf `.local` im eigenen Netz, `myhostname` der eigene Rechnername. Der **erste Treffer gewinnt**. Ein veralteter Eintrag in /etc/hosts schlägt also jede DNS-Antwort, und host und dig merken davon nichts. Darum testest du die Auflösung „wie ein Programm“ mit **`getent hosts NAME`**. Liefern getent und dig verschiedene Adressen, steht etwas in /etc/hosts.

Viele Systeme nutzen **systemd-resolved**. Dann steht in /etc/resolv.conf nur `nameserver 127.0.0.53`, ein lokaler Zwischenspeicher (Stub), und die echten Server zeigt `resolvectl status`. `resolvectl query NAME` fragt über ihn, `resolvectl flush-caches` leert den Zwischenspeicher. In nsswitch.conf steht dann oft `resolve` statt `dns`.
</Karte>

<Merke>Programme fragen über nsswitch.conf, hosts: files dns heißt erst /etc/hosts, dann DNS, erster Treffer gewinnt. getent hosts testet wie ein Programm, host und dig nur DNS. systemd-resolved: 127.0.0.53, resolvectl status, resolvectl query.</Merke>
