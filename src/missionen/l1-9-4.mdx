Der Logserver der Firma steht in einem anderen Netz, `10.20.0.0/16`. Erreichbar ist er nur über das Labor-Gateway `192.168.1.254`, und das weiß werkstatt noch nicht. **Deine Mission: Stelle Adressen, Schnittstellen und Routen mit iproute2 von Hand ein und lies auch die alten net-tools.** Lernziel 109.3.

## Adressen und Schnittstellen mit ip

<Karte nr={1} titel="iproute2: ein Befehl für alles">
Das Paket **iproute2** bringt den Befehl `ip`. Er hat Objekte: `link` (die Schnittstelle selbst), `addr` (Adressen), `route` (Routen), `neigh` (Nachbarn, also die ARP-Tabelle). Jedes Objekt und jeder Unterbefehl darf abgekürzt werden: `ip a` = `ip addr show`, `ip r` = `ip route show`.

| Befehl | Wirkung |
|---|---|
| `ip addr` / `ip a` | alle Schnittstellen mit Adressen |
| `ip -br a` | kurz, eine Zeile pro Schnittstelle |
| `ip -4 a` / `ip -6 a` | nur IPv4 oder IPv6 |
| `ip link` | Schnittstellen mit MAC-Adresse und Zustand |
| `sudo ip addr add 10.20.30.10/26 dev enp0s31f6` | Adresse hinzufügen (eine Schnittstelle kann viele haben) |
| `sudo ip addr del 10.20.30.10/26 dev enp0s31f6` | Adresse entfernen |
| `sudo ip addr flush dev enp0s31f6` | alle Adressen entfernen |
| `sudo ip link set enp0s31f6 down` / `up` | Schnittstelle aus- oder einschalten |

In der Ausgabe von `ip link` heißt `state UP` mit `LOWER_UP`: Die Schnittstelle ist an und hat Verbindung. `NO-CARRIER` heißt: an, aber kein Kabel oder kein Funknetz. Fehlt `UP`, ist sie aus.

**Wichtig:** Alles, was du mit `ip` einstellst, wirkt sofort, ist aber nach einem Neustart weg. Für Dauerhaftes nimmst du NetworkManager oder die Dateien aus Mission 9.3. Und noch etwas: Läuft NetworkManager, kann er beim nächsten Verbindungsaufbau deine Handarbeit überschreiben.
</Karte>

<Merke>ip a, ip -br a, ip link, ip r, ip neigh zum Anschauen. ip addr add/del ADR/P dev X, ip link set X up/down zum Ändern. Wirkt sofort, ist nach dem Neustart weg.</Merke>

## Routen

<Karte nr={2} titel="Routing: Welcher Weg für welches Ziel?">
Für jedes Paket sucht der Kernel in der **Routingtabelle** den passendsten Eintrag, also den mit dem längsten Präfix. Ein Netz, an dem eine Schnittstelle direkt hängt, steht von selbst drin (`proto kernel scope link`). Für alles andere braucht es eine Route über einen Router. Die **Standardroute** `default` (gleich `0.0.0.0/0`) passt auf jedes Ziel und wird genommen, wenn nichts Genaueres passt.

```
default via 192.168.1.1 dev enp0s31f6 proto dhcp metric 100
192.168.1.0/24 dev enp0s31f6 proto kernel scope link src 192.168.1.23
```

| Befehl | Wirkung |
|---|---|
| `sudo ip route add 10.20.0.0/16 via 192.168.1.254` | Netz über einen bestimmten Router |
| `sudo ip route add default via 192.168.1.1` | Standardroute setzen |
| `sudo ip route del default` | Standardroute löschen |
| `sudo ip route replace default via 192.168.1.1` | ersetzen statt Fehler „File exists“ |
| `ip route get 10.20.0.5` | Welche Route nimmt dieses Ziel? |

Der Router hinter `via` muss direkt erreichbar sein, also in einem Netz liegen, an dem werkstatt hängt. Sonst meldet ip „Nexthop has invalid gateway“. Gibt es mehrere Standardrouten, gewinnt die mit der kleineren **Metrik**.
</Karte>

<Merke>Längstes passendes Präfix gewinnt, default passt immer. ip route add NETZ via GW, ip route add default via GW, ip route del, ip route get ZIEL. Das Gateway muss im eigenen Netz liegen.</Merke>

<Karte nr={3} titel="Die alten net-tools">
Vor iproute2 gab es das Paket **net-tools**. Es gilt als veraltet und fehlt auf neuen Systemen oft, aber in alten Anleitungen und Skripten begegnet es dir ständig. Die Prüfung erwartet, dass du die Befehle lesen kannst.

| net-tools | iproute2 |
|---|---|
| `ifconfig` | `ip addr` |
| `ifconfig enp0s31f6 192.168.1.60 netmask 255.255.255.0 up` | `ip addr add 192.168.1.60/24 dev enp0s31f6` und `ip link set enp0s31f6 up` |
| `route -n` / `netstat -rn` | `ip route` |
| `route add default gw 192.168.1.1` | `ip route add default via 192.168.1.1` |
| `route add -net 10.20.0.0 netmask 255.255.0.0 gw 192.168.1.254` | `ip route add 10.20.0.0/16 via 192.168.1.254` |
| `arp -n` | `ip neigh` |
| `netstat -tulpn` | `ss -tulpn` |
| `netstat -i` | `ip -s link` |

In `route -n` stehen die Flags `U` (Route ist aktiv) und `G` (über ein Gateway). Die Option `-n` zeigt Zahlen statt Namen, das geht schneller und hängt nicht, wenn DNS kaputt ist.
</Karte>
