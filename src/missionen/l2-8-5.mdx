Die Firma will einen öffentlichen Nameserver für die Außenstelle aufstellen, auf AlmaLinux. Der Sicherheitsbeauftragte hat drei Bedingungen: named darf nicht als root laufen, er soll in einem Käfig stecken, und von außen darf niemand sehen, welche Version läuft oder welche Rechner es gibt. **Deine Mission: Installier BIND auf labor-alma, prüf, unter welchem Benutzer er läuft, verbirg Version und Zone und sperr ihn in einen Käfig.** Lernziel 207.3.

## Weniger Rechte

<Karte nr={1} titel="Nicht als root">
named muss als root starten, weil nur root Port 53 öffnen darf. Danach gibt er die Rechte ab und läuft als einfacher Benutzer weiter: `named -u named` auf Red Hat, `named -u bind` auf Debian. Beide Pakete legen den Benutzer an, mit `/sbin/nologin` als Shell (Debian: `/usr/sbin/nologin`), damit sich niemand damit anmelden kann.

Der Benutzer braucht nur wenig:

- Lesen: `/etc/named.conf` (root:named, Modus 640, damit Schlüssel darin geschützt sind), Zonendateien, Schlüssel.
- Schreiben: nur sein Arbeitsverzeichnis für sekundäre Zonen und Journale (`/var/named/slaves`, `/var/named/dynamic` auf Red Hat, `/var/cache/bind` auf Debian) und die Protokolldateien.

Gehören die Zonendateien named selbst, könnte ein Angreifer, der named übernimmt, sie umschreiben. Darum gehören sie root und sind für named nur lesbar.
</Karte>

## Der Käfig

<Karte nr={2} titel="chroot">
Mit `-t VERZEICHNIS` ruft named nach dem Start `chroot()` auf. Von da an ist das Verzeichnis für ihn `/`, alles außerhalb existiert nicht mehr. Selbst wer named übernimmt, sieht nur den Käfig.

Auf **Red Hat** erledigt das Paket **bind-chroot** die Arbeit: Es bringt die Unit **named-chroot** mit, die `named -u named -t /var/named/chroot` startet. Davor hängt ein Hilfsdienst (`named-chroot-setup`) `/etc/named.conf`, `/var/named` und die übrigen Dateien per bind-mount in den Käfig. Man pflegt die Dateien also weiter an der gewohnten Stelle. Die normale Unit named muss dafür aus sein:

```
sudo dnf install bind-chroot
sudo systemctl disable --now named
sudo systemctl enable --now named-chroot
```

Auf **Debian** gibt es kein fertiges Paket. Man baut den Käfig von Hand (etwa `/var/lib/named` mit `etc/bind`, `var/cache/bind`, `dev/null`, `dev/random`), kopiert die Konfiguration hinein und setzt in `/etc/default/named` `OPTIONS="-u bind -t /var/lib/named"`. Wichtig ist in beiden Fällen: Alle Pfade in named.conf gelten danach **innerhalb** des Käfigs.
</Karte>

## Wenig verraten

<Karte nr={3} titel="Version und Zone">
Jeder kann einen BIND-Server nach seiner Version fragen, über eine Sonderzone in der Klasse CHAOS:

```
dig @192.0.2.53 version.bind chaos txt +short
"9.16.23-RH"
```

Für einen Angreifer ist das die halbe Arbeit: Er schlägt nach, welche Lücken diese Version hat. Mit `version none;` (oder einem beliebigen Text wie `version "geheim";`) in den Optionen antwortet named ohne Inhalt. `hostname none;` und `server-id none;` verbergen auf dieselbe Weise den Rechnernamen. Das schützt nicht vor der Lücke selbst, nur vor dem Finden. Updates bleiben Pflicht.

Mehr verrät ein offener Zonentransfer, nämlich alle Namen auf einmal. Darum `allow-transfer { none; };` in die Optionen und nur in den Zonen mit sekundärem Server dessen Adresse oder Schlüssel freigeben. Dazu `allow-update { none; };`, wenn niemand die Zone dynamisch ändern soll (auf Red Hat steht das schon bei den mitgelieferten Zonen), und auf einem öffentlichen zuständigen Server `recursion no;`.
</Karte>

<Merke>named startet als root, läuft mit -u als named oder bind. Käfig mit -t, auf Red Hat per bind-chroot und named-chroot. version none; verbirgt die Version, allow-transfer \{ none; \}; global sperrt Zonentransfers.</Merke>
