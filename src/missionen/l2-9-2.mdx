intern.lab.example.org ist von überall erreichbar, auch aus dem Netz der Firma. Das Maschinenbuch unter /doku soll nur das Wartungsteam sehen, und Max möchte die Doku selbst pflegen, ohne an die Apache-Konfiguration zu müssen. **Deine Mission: Beschränk intern auf das Labornetz, schütz /doku mit Benutzern und Gruppen per .htaccess und lege eine Umleitung an.** Lernziel 208.1.

## Wer darf?

<Karte nr={1} titel="Require">
Seit Apache 2.4 regelt **mod_authz_core** den Zugriff mit `Require`, meist in einem `<Directory>`-Block:

```
<Directory /var/www/intern>
    Require ip 192.168.1.0/24
</Directory>
```

| Zeile | Wer darf |
|---|---|
| `Require all granted` / `denied` | alle / niemand |
| `Require ip 192.168.1.0/24 10.20` | Adressen und Netze (mod_authz_host) |
| `Require host lab.example.org` | Rechner, deren Name per DNS passt |
| `Require local` | der Server selbst |
| `Require valid-user` | jeder angemeldete Benutzer (mod_authz_user) |
| `Require user lena max` | nur diese Benutzer |
| `Require group team` | Mitglieder der Gruppe (mod_authz_groupfile) |

Mehrere `Require`-Zeilen bedeuten „eine genügt“ (wie `<RequireAny>`). `<RequireAll>` verlangt alle, darin schließt `Require not ip …` aus. Abgelehnt wird mit **403**, im error.log steht `AH01630: client denied by server configuration`.

Aus Apache 2.2 stammen `Order`, `Allow` und `Deny`. Sie funktionieren nur mit **mod_access_compat** weiter und sollten nicht mit `Require` gemischt werden:

```
Order deny,allow        # erst Deny, dann Allow; was in keiner Liste steht: erlaubt
Deny from all
Allow from 192.168.1.0/24
```
</Karte>

## Wer bist du?

<Karte nr={2} titel="Basic-Anmeldung und htpasswd">
```
<Directory /var/www/intern/doku>
    AuthType Basic
    AuthName "Maschinenbuch"
    AuthUserFile /etc/apache2/htpasswd
    Require valid-user
</Directory>
```

**AuthType Basic** schickt Benutzer und Passwort nur Base64-kodiert, also im Klartext mit. Darum gehört Basic-Anmeldung hinter HTTPS (Mission 9.4). **AuthName** ist der Text im Anmeldefenster des Browsers. **AuthUserFile** nennt die Datei mit den Benutzern. Sie liegt außerhalb von DocumentRoot und ist für Apache lesbar.

Die Datei pflegt **htpasswd** (Paket apache2-utils bzw. httpd-tools):

```
sudo htpasswd -c /etc/apache2/htpasswd lena    # -c: Datei neu anlegen, fragt nach dem Passwort
sudo htpasswd /etc/apache2/htpasswd max        # weiteren Benutzer hinzufügen (ohne -c!)
sudo htpasswd -b /etc/apache2/htpasswd max PW  # Passwort auf der Befehlszeile, für Skripte
sudo htpasswd -D /etc/apache2/htpasswd max     # löschen
```

`-c` auf eine vorhandene Datei löscht alle bisherigen Benutzer. Standard ist MD5 (`$apr1$`), `-B` nimmt bcrypt.

Gruppen stehen in einer einfachen Textdatei, eine Zeile je Gruppe: `team: max lena`. Sie wird mit **AuthGroupFile** eingebunden und mit `Require group team` abgefragt. Auf Debian ist das zuständige Modul **authz_groupfile** nicht eingeschaltet. Ohne `a2enmod authz_groupfile` gibt es einen Fehler 500.
</Karte>

## Ohne Neustart: .htaccess

<Karte nr={3} titel=".htaccess und AllowOverride">
Eine Datei **.htaccess** in einem Verzeichnis enthält Direktiven, die für dieses Verzeichnis gelten. Apache liest sie bei jeder Anfrage, Änderungen wirken also sofort und ohne root. Ob und was darin stehen darf, bestimmt **AllowOverride** im `<Directory>` des Servers:

| AllowOverride | erlaubt in .htaccess |
|---|---|
| `None` | nichts, die Datei wird gar nicht gelesen (Standard in Debian und Red Hat) |
| `AuthConfig` | AuthType, AuthName, AuthUserFile, AuthGroupFile, Require |
| `Limit` | Order, Allow, Deny |
| `FileInfo` | Redirect, ErrorDocument, RewriteRule, AddType |
| `Indexes` | DirectoryIndex, IndexOptions |
| `Options` | Options |
| `All` | alles |

Steht in der .htaccess etwas Unerlaubtes oder ein Tippfehler, antwortet Apache für das ganze Verzeichnis mit **500**, im error.log steht `[core:alert]` mit Datei und Grund. Abrufen lässt sich die .htaccess selbst nicht: Debian sperrt alle Dateien, die mit `.ht` beginnen.

Umleitungen setzt **mod_alias**: `Redirect permanent /plan http://intern.lab.example.org/schichtplan.txt` antwortet mit 301 und dem neuen Ort im Kopf `Location`. `temp` (302, Standard), `seeother` (303) und `gone` (410) gibt es auch, `RedirectMatch` nimmt einen regulären Ausdruck.
</Karte>

<Merke>Require ip für Netze, Require valid-user/user/group nach AuthType Basic. htpasswd -c nur beim ersten Benutzer. .htaccess wirkt nur mit passendem AllowOverride, Fehler darin = 500. 401 heißt anmelden, 403 heißt nie.</Merke>
