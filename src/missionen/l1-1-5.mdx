Manchmal startet ein System nicht mehr richtig: Ein Treiber hängt, ein Dienst blockiert, das Root-Passwort ist vergessen. Dann gibst du dem Kernel beim Start eine Anweisung mit und liest danach nach, was passiert ist. **Deine Mission: Setze Kernelparameter und lies die Bootmeldungen.** Lernziel 101.2.

## Kernelparameter

<Karte nr={1} titel="Im GRUB-Menü eingreifen">
Erscheint das GRUB-Menü, markierst du einen Eintrag und drückst **e**. Du siehst dann die Befehle, mit denen GRUB startet, darunter eine Zeile, die mit `linux` beginnt:

```
linux /boot/vmlinuz-6.1.0-27-amd64 root=UUID=3f1c… ro quiet
```

Alles hinter dem Kernel sind **Kernelparameter**. Du hängst etwas an, etwa `systemd.unit=rescue.target`, und startest mit **Strg+X** oder **F10**. Die Änderung gilt **nur für diesen einen Start**. Dauerhaft ändert man Parameter in `/etc/default/grub` und erzeugt danach die Konfiguration neu. Das kommt in Akt 2.

Taucht das Menü gar nicht auf, hilft es oft, beim Start die **Umschalttaste** (BIOS) oder **Esc** (UEFI) gedrückt zu halten.
</Karte>

<Merke>e im GRUB-Menü, Parameter an die linux-Zeile, Strg+X. Gilt nur für diesen Start.</Merke>

<Karte nr={2} titel="Die wichtigsten Parameter">
| Parameter | Wirkung |
| --- | --- |
| `ro` / `rw` | Wurzeldateisystem erst nur lesbar (später wird es meist beschreibbar eingehängt) oder gleich beschreibbar |
| `root=` | wo das Wurzeldateisystem liegt |
| `quiet` | weniger Meldungen auf dem Bildschirm |
| `systemd.unit=rescue.target` | Rettungsmodus. Kurzformen: `rescue`, `single`, `s`, `S` oder `1` |
| `systemd.unit=emergency.target` | Notfallmodus, noch weniger. Kurzform: `emergency` |
| `3` oder `5` | in den alten Runlevel 3 oder 5 starten (systemd übersetzt das) |
| `init=/bin/bash` | statt des Init-Systems direkt eine Shell als PID 1 |
| `modprobe.blacklist=name` | ein Modul für diesen Start sperren |
| `modul.parameter=wert` | einem fest eingebauten oder geladenen Modul einen Parameter mitgeben |

Welche Parameter das laufende System bekommen hat, steht in **/proc/cmdline**.
</Karte>

<Merke>/proc/cmdline zeigt die Parameter, mit denen das laufende System gestartet wurde.</Merke>

<Hinweis art="sicherheit" titel="init=/bin/bash">
Mit init=/bin/bash bekommt jeder, der am Rechner sitzt, eine Root-Shell, ganz ohne Passwort. So setzt man ein vergessenes Root-Passwort zurück. Es zeigt aber auch: Wer physischen Zugang zum Rechner hat, hat ihn ohne weiteren Schutz (Passwort für GRUB, verschlüsselte Platte) praktisch übernommen. Mehr dazu in Topic 110.
</Hinweis>

## Bootmeldungen lesen

<Karte nr={3} titel="dmesg: der Ringpuffer">
Alles, was der Kernel meldet, schreibt er in einen Speicherbereich fester Größe, den **Ringpuffer**. Ist er voll, überschreiben neue Meldungen die ältesten. `dmesg` gibt ihn aus. Nützliche Optionen: `-T` zeigt die Uhrzeit statt Sekunden seit dem Start, `-H` macht die Ausgabe lesbarer, `-l err,warn` zeigt nur Fehler und Warnungen, `-w` wartet auf neue Meldungen.

Debian und Ubuntu erlauben das Lesen des Ringpuffers nur root. Als normaler Benutzer kommt dann „dmesg: read kernel buffer failed: Operation not permitted“. Mit `sudo dmesg` geht es.
</Karte>

<Karte nr={4} titel="journalctl: das Journal von systemd">
systemd sammelt die Meldungen von Kernel **und** Diensten im **Journal**. `journalctl` liest es:

| Befehl | Zeigt |
| --- | --- |
| `journalctl -b` | alles seit dem aktuellen Start |
| `journalctl -b -1` | den vorigen Start |
| `journalctl --list-boots` | alle gespeicherten Starts |
| `journalctl -k` | nur Kernelmeldungen, wie dmesg |
| `journalctl -p err` | nur Fehler und Schlimmeres |
| `journalctl -u ssh` | nur eine Unit |

Den vorigen Start gibt es nur, wenn das Journal **dauerhaft** gespeichert wird, also im Verzeichnis `/var/log/journal`. Sonst liegt es nur im Arbeitsspeicher und ist nach dem Neustart weg. Auf manchen Systemen stehen Bootmeldungen außerdem klassisch in `/var/log/boot.log` oder `/var/log/messages`.
</Karte>

<Merke>dmesg = Kernel jetzt. journalctl -b = Kernel und Dienste seit dem Start, -b -1 = voriger Start.</Merke>
