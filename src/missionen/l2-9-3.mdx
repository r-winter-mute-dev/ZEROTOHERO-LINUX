## Prozesse und Threads

<Karte nr={1} titel="Multi-Processing-Module">
Wie Apache Anfragen auf Prozesse verteilt, entscheidet genau ein **MPM**:

| MPM | Arbeitsweise | typische Direktiven |
|---|---|---|
| **prefork** | ein Prozess je Verbindung, keine Threads | StartServers, MinSpareServers, MaxSpareServers |
| **worker** | mehrere Prozesse mit je vielen Threads | StartServers, ThreadsPerChild, MinSpareThreads, MaxSpareThreads |
| **event** | wie worker, ruhende Keep-Alive-Verbindungen belegen keinen Thread | wie worker, Standard auf Debian und Red Hat |

Für alle gilt: **MaxRequestWorkers** (früher MaxClients) ist die Obergrenze gleichzeitig bearbeiteter Anfragen, weitere warten in der Warteschlange. **ServerLimit** ist die harte Grenze für Prozesse, bei prefork 256. Wer mehr MaxRequestWorkers will, muss auch ServerLimit erhöhen, sonst kürzt Apache und warnt mit `AH00180`. **MaxConnectionsPerChild** (früher MaxRequestsPerChild) beendet einen Kindprozess nach so vielen Verbindungen, 0 heißt nie. Das hilft gegen Speicherlecks.

Auf Debian stehen die Werte in `mods-available/mpm_*.conf`, `a2query -M` zeigt das aktive MPM. Auf Red Hat wählt `conf.modules.d/00-mpm.conf` das MPM, eigene Werte kommen in eine Datei in `conf.d`.

Eine grobe Rechnung: Ein prefork-Prozess mit PHP braucht 30 bis 60 MB. Bei 2 GB für Apache sind also höchstens rund 40 sinnvoll, sonst lagert der Rechner aus und wird erst recht langsam. (Grobe Faustregel, nicht geprüft. Miss den eigenen Speicherbedarf mit ps.)
</Karte>

## Skriptsprachen

<Karte nr={2} titel="PHP und Perl">
**mod_php** führt PHP im Apache-Prozess aus. Es ist nicht threadsicher, darum verlangt es prefork. Auf Debian schaltet `apt install libapache2-mod-php8.2` das MPM selbst um: event aus, prefork an, dann php8.2. Danach liefert Apache `.php` ausgeführt statt als Quelltext. Ohne Modul gibt er die Datei mit ihrem Quelltext heraus, samt Passwörtern darin.

Auf **Red Hat 9** gibt es kein mod_php. `dnf install php` bringt **php-fpm** mit, einen eigenen Dienst, und `/etc/httpd/conf.d/php.conf`, das `.php` per `SetHandler "proxy:unix:/run/php-fpm/www.sock|fcgi://localhost"` an php-fpm weiterreicht (mod_proxy_fcgi). Läuft php-fpm nicht, antwortet Apache mit 503. php-fpm wird mit httpd zusammen gestartet (Wants in einer Drop-in-Datei, nicht geprüft) und lässt sich mit `systemctl enable --now php-fpm` auch selbst einschalten. php-fpm ginge auch auf Debian (Paket php8.2-fpm, `a2enconf php8.2-fpm`), dann darf event bleiben.

Perl läuft mit **mod_perl** (Debian: libapache2-mod-perl2) im Server, etwa mit `PerlResponseHandler`. In der Praxis ist es selten geworden, in den Lernzielen steht es noch.
</Karte>

## Den Server beobachten

<Karte nr={3} titel="mod_status">
**mod_status** zeigt unter `/server-status`, was Apache gerade tut: Laufzeit, Anfragen pro Sekunde, beschäftigte und freie Worker und eine Anzeigetafel (`_` wartet, `W` sendet, `K` Keep-Alive, `.` frei). `?auto` liefert dasselbe maschinenlesbar für Überwachungsprogramme. Debian schaltet das Modul ein, erlaubt aber nur `Require local`. Wer aus dem Labornetz schauen will, ergänzt in `mods-available/status.conf` eine Zeile `Require ip 192.168.1.0/24`.

Daneben: `ps -C apache2` zählt die Prozesse, die Protokolle zeigen, was gefragt wird. `Timeout`, `KeepAlive`, `MaxKeepAliveRequests` und `KeepAliveTimeout` in apache2.conf bestimmen, wie lange Verbindungen offen bleiben.
</Karte>
