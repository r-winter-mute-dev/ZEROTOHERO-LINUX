Die Buchhaltung ist unzufrieden: Der CSV-Export von lagerist 2.4.1 zerlegt Bezeichnungen wie „Unterlegscheibe 6,4 mm“ in zu viele Spalten. Auf der Mailingliste der Entwickler gibt es schon einen Patch, eine neue Version noch nicht. **Deine Mission: Spiel den Patch ein, bau lagerist neu, beweis mit den Tests, dass der Fehler weg ist, und installiere sauber, so dass du es später wieder entfernen kannst.** Lernziel 206.1.

## Patches

<Karte nr={1} titel="diff und patch">
Ein **Patch** beschreibt Änderungen an Textdateien. `diff -u alt neu` erzeugt ihn im **unified format**:

```
--- a/src/export.c
+++ b/src/export.c
@@ -1,11 +1,23 @@
 #include <stdio.h>
+#include <string.h>
 #include "lagerist.h"
```

`---` und `+++` nennen die alte und die neue Datei. Jeder Abschnitt (**Hunk**) beginnt mit `@@ -Start,Zeilen +Start,Zeilen @@`. Zeilen mit `-` fallen weg, mit `+` kommen dazu, mit Leerzeichen bleiben sie als Kontext.

**patch** spielt die Änderung ein. Die Pfade im Kopf beginnen oft mit `a/` und `b/` (so schreibt git sie). Darum ruft man im Quellbaum `patch -p1` auf: `-p1` schneidet den ersten Pfadteil ab, aus `a/src/export.c` wird `src/export.c`.

```
patch -p1 --dry-run < ../lagerist-2.4.1-csv.patch   # nur prüfen
patch -p1 < ../lagerist-2.4.1-csv.patch             # einspielen
patch -R -p1 < ../lagerist-2.4.1-csv.patch          # zurücknehmen
zcat fix.patch.gz | patch -p1                       # gepackter Patch
```

Passt ein Hunk nicht, landet er in `DATEI.rej`. Genau so hast du in Akt 2 den Kernel gepatcht.
</Karte>

## Installieren und wieder loswerden

<Karte nr={2} titel="install, DESTDIR und make uninstall">
Hinter `make install` steckt meist das Programm **install** aus coreutils. Es kopiert und setzt dabei Rechte, Besitzer und Gruppe in einem Schritt:

```
sudo install -m 0755 -o root -g root src/lagerist /usr/local/bin/
sudo install -d -m 2770 -g lena /var/lib/lagerist          # Verzeichnis
sudo install -D -m 0644 lagerist.conf /etc/lagerist/lagerist.conf   # Ordner mit anlegen
```

Ohne `-m` bekommt die Kopie **0755**, nicht die Rechte des Originals wie bei `cp`.

Selbst gebaute Programme kennt kein Paketmanager. Drei Wege halten Ordnung:

- **`make uninstall`** entfernt, was `make install` kopiert hat. Es liest die Pfade aus dem **aktuellen** Makefile. Den konfigurierten Quellbaum also aufheben und vor einem neuen `configure` mit anderem `--prefix` erst deinstallieren.
- **`make DESTDIR=/tmp/stage install`** installiert in einen Zwischenordner. So siehst du ohne Root-Rechte, welche Dateien entstehen, und kannst daraus ein Paket bauen.
- Ein eigenes Präfix wie `--prefix=/opt/lagerist` hält alles in einem Ordner zusammen.

`make clean` löscht die Objektdateien, `make distclean` zusätzlich alles, was configure erzeugt hat.
</Karte>

<Merke>patch -p1 im Quellbaum, erst mit --dry-run. install kopiert und setzt Rechte in einem Schritt. Vor einem neuen configure erst make uninstall.</Merke>
