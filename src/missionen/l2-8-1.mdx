## Was ein Nameserver tut

<Karte nr={1} titel="Zuständig oder zwischengespeichert">
Ein Nameserver kann zwei Rollen haben:

- **Autoritativ** (zuständig) für eine Zone: Er kennt die Antworten selbst, aus seinen Zonendateien, und setzt in der Antwort das Flag **aa** (authoritative answer).
- **Rekursiv** mit Cache: Er kennt die Antwort nicht, fragt sich für den Client von der Wurzel über die Top-Level-Domain bis zum zuständigen Server durch und merkt sich das Ergebnis. Ein **caching-only** Server hat gar keine eigenen Zonen.

Der bekannteste Nameserver ist **BIND 9** vom ISC, das Programm heißt **named**. Daneben gibt es **dnsmasq** (klein, DNS-Weiterleitung mit Cache und DHCP in einem, beliebt auf Routern), **djbdns** von D. J. Bernstein (strikt getrennt: tinydns zuständig, dnscache rekursiv) und **PowerDNS** (Authoritative Server mit Datenbank-Backends und ein eigener Recursor).

Ein rekursiver Server, der jedem im Internet antwortet, heißt **offener Resolver**. Angreifer missbrauchen solche Server für Verstärkungsangriffe. Rekursion gibt es darum nur für die eigenen Netze.
</Karte>

## BIND auf Debian und Red Hat

<Karte nr={2} titel="Wo was liegt">
| | Debian | Red Hat |
|---|---|---|
| Paket | `bind9`, Werkzeuge `bind9-utils` | `bind`, Werkzeuge `bind-utils` |
| Hauptdatei | `/etc/bind/named.conf` | `/etc/named.conf` |
| Eigene Zonen | `/etc/bind/named.conf.local` | in `/etc/named.conf` |
| Optionen | `/etc/bind/named.conf.options` | in `/etc/named.conf` |
| Arbeitsverzeichnis | `/var/cache/bind` | `/var/named` |
| Zonendateien | meist `/etc/bind/db.*` | `/var/named/*` |
| Wurzelserver | `/usr/share/dns/root.hints` | `/var/named/named.ca` |
| Benutzer | `bind` | `named` |
| Dienst | `named` (Alias `bind9`) | `named` |

Die Lernziele nennen `/etc/named.conf` und `/var/named/`, also die Red-Hat-Pfade. Auf Debian ist die Datei in mehrere Teile zerlegt, die `named.conf` mit `include` zusammenführt.

Die Syntax ist überall gleich: Anweisungen enden mit `;`, Blöcke stehen in `{ }`, und auch nach der schließenden Klammer steht ein `;`. Kommentare beginnen mit `//` oder `#` oder stehen zwischen `/*` und `*/`. Ein fehlendes Semikolon ist der häufigste Grund, warum named nicht startet. **named-checkconf** findet es.
</Karte>

<Karte nr={3} titel="Ein Cache fürs Labor">
```
acl labor {
    192.168.1.0/24;
    localhost;
};

options {
    directory "/var/cache/bind";
    listen-on { 127.0.0.1; 192.168.1.23; };
    listen-on-v6 { ::1; };
    allow-query { labor; };
    allow-recursion { labor; };
    forwarders { 192.168.1.1; };
    forward first;
    dnssec-validation auto;
};
```

**acl** gibt einer Liste von Adressen einen Namen. Eingebaut sind `any`, `none`, `localhost` (die eigenen Adressen) und `localnets` (die Netze an den eigenen Schnittstellen). **listen-on** legt fest, auf welchen Adressen named lauscht. **allow-query** regelt, wer überhaupt fragen darf, **allow-recursion**, wer rekursive Antworten bekommt. Mit **forwarders** schickt named Anfragen, die er nicht selbst kennt, an andere Server. `forward first` fragt danach selbst weiter, wenn die Weiterleitung scheitert, `forward only` gibt dann auf. `recursion no;` macht einen rein zuständigen Server.
</Karte>

<Merke>named.conf: Semikolon nach jeder Anweisung, auch nach \}. Rekursion nur für die eigenen Netze, mit acl und allow-recursion. Vor jedem Neustart named-checkconf.</Merke>
