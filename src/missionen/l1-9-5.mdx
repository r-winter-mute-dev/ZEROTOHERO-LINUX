„Das Internet geht nicht“, sagt Lena. Das kann ein Dutzend Ursachen haben. **Deine Mission: Such Netzwerkfehler mit System, von der Schnittstelle bis zum Dienst, und lies, was ping, traceroute, tracepath, nc und ss dir sagen.** Lernziel 109.3.

## Von unten nach oben

<Karte nr={1} titel="Fehlersuche in sechs Stufen">
Jede Stufe setzt die vorige voraus. Wer unten anfängt, findet den Fehler schnell und sucht nie an der falschen Stelle.

1. **Link:** Ist die Schnittstelle an und hat sie Verbindung? `ip link`: Steht `UP` und `LOWER_UP` da, oder `NO-CARRIER`?
2. **Adresse:** Hat sie eine passende Adresse und Maske? `ip a`. Eine Adresse aus `169.254.0.0/16` heißt: Kein DHCP-Server hat geantwortet.
3. **Gateway:** Antwortet der eigene Router? `ping -c 4 192.168.1.1`.
4. **Route:** Gibt es eine Standardroute, und kommt man ins Netz dahinter? `ip r`, dann `ping -c 4 203.0.113.80`, eine IP ohne Namen.
5. **Name:** Wird der Name aufgelöst? `getent hosts www.example.org`, `host www.example.org`. Klappt Stufe 4, aber nicht Stufe 5, ist es DNS.
6. **Dienst:** Lauscht der Dienst? Beim Gegenüber mit `nc -zv www.example.org 443`, auf dem eigenen Rechner mit `ss -tulpn`.

**ping** schickt ICMP-Echo-Anfragen. Ohne `-c` läuft es endlos, bis Strg+C. Was die Meldungen bedeuten:

| Meldung | Bedeutung |
|---|---|
| `connect: Network is unreachable` | Der Kernel hat keine passende Route, das Paket verlässt den Rechner nicht. |
| `Destination Host Unreachable` (von der eigenen Adresse) | Im lokalen Netz antwortet niemand auf ARP unter dieser Adresse. |
| nur `100% packet loss` | Pakete gehen raus, aber keine Antwort. Unterwegs gefiltert oder Weg kaputt. |
| `Temporary failure in name resolution` | Kein DNS-Server erreichbar. |
| `Name or service not known` | Der Name existiert nirgends. |

Für IPv6 gibt es `ping6` oder `ping -6`.
</Karte>

<Merke>Link, Adresse, Gateway, Route, Name, Dienst, in dieser Reihenfolge. ping IP geht, ping Name nicht: DNS. Network is unreachable: keine Route. Host Unreachable: niemand im lokalen Netz. ping -c 4 begrenzt.</Merke>

## Den Weg verfolgen

<Karte nr={2} titel="traceroute und tracepath">
Jedes IP-Paket hat einen Zähler **TTL** (time to live), den jeder Router um eins verringert. Bei null wirft er das Paket weg und schickt eine ICMP-Meldung „Time exceeded“ zurück. **traceroute** nutzt das: Es schickt Pakete mit TTL 1, 2, 3 und so weiter, und jeder Router auf dem Weg verrät sich mit seiner Meldung. So siehst du, **wo** die Verbindung abreißt.

- `* * *` heißt: Von diesem Hop kam keine Antwort. Einzelne Sterne mitten im Weg sind oft harmlos, weil manche Router keine Meldungen schicken. Hören die Antworten ab einem Punkt ganz auf, liegt dort das Problem.
- `!H` heißt: Host nicht erreichbar.
- **tracepath** macht dasselbe, braucht nie Root-Rechte und zeigt zusätzlich die **MTU** (pmtu), also die größte Paketgröße auf dem Weg.
- Für IPv6: `traceroute6`, `tracepath6` oder jeweils `-6`.

Ob ein Dienst antwortet, prüft **netcat** (`nc`): `nc -zv HOST PORT` versucht nur den Verbindungsaufbau (`-z`) und meldet das Ergebnis (`-v`). `Connection refused` heißt: Rechner erreichbar, aber auf dem Port lauscht nichts. `timed out` heißt: Eine Firewall verwirft die Pakete, oder der Weg ist kaputt. Mit `nc -l -p 5000` lauscht nc selbst auf einem Port, gut zum Testen von Firewalls.

Welche Ports auf dem **eigenen** Rechner offen sind, zeigt **ss** (Nachfolger von `netstat`): `ss -tulpn` heißt TCP, UDP, nur lauschend (listening), mit Prozess, Zahlen statt Namen. `ss -tn` zeigt bestehende TCP-Verbindungen. Den Prozess sieht nur root.
</Karte>

<Merke>traceroute und tracepath zeigen den Weg, * * * heißt keine Antwort, tracepath ohne root und mit MTU. nc -zv HOST PORT: refused = Port zu, timed out = gefiltert. ss -tulpn: eigene lauschende Ports.</Merke>
