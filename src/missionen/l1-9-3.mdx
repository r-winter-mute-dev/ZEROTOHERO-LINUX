## Name und Namensdateien

<Karte nr={1} titel="Vier Dateien, die jeder Rechner hat">
- **/etc/hostname** enthält nur den Namen des Rechners, eine Zeile. Er wird beim Start gelesen. `hostname neuername` ändert den Namen sofort, aber nur bis zum Neustart. **`hostnamectl set-hostname neuername`** ändert beides, den laufenden Namen und die Datei. Ohne Argument zeigt `hostnamectl` Name, Betriebssystem und Kernel.
- **/etc/hosts** ordnet Adressen Namen zu, eine Zeile pro Adresse: zuerst die IP, dann der Name, dann Aliase. `127.0.0.1 localhost` steht immer drin. Debian trägt den eigenen Namen auf `127.0.1.1` ein.
- **/etc/resolv.conf** nennt die DNS-Server (`nameserver 192.168.1.1`, höchstens drei) und Suchdomänen (`search lab.example.org`). Bei einem kurzen Namen wie `labor2` hängt der Resolver die Suchdomäne an. Auf den meisten Systemen schreibt NetworkManager oder systemd-resolved diese Datei. Von Hand geänderte Zeilen verschwinden dann beim nächsten Verbindungsaufbau.
- **/etc/nsswitch.conf** legt fest, in welcher Reihenfolge Namen gesucht werden. Die Zeile `hosts: files dns` heißt: zuerst /etc/hosts, dann DNS. Mehr dazu in Mission 9.6.
</Karte>

<Merke>/etc/hostname: der Name. hostnamectl set-hostname: dauerhaft, hostname: nur jetzt. /etc/hosts: IP Name Aliase. /etc/resolv.conf: nameserver und search, oft automatisch erzeugt. /etc/nsswitch.conf: Reihenfolge.</Merke>

## NetworkManager

<Karte nr={2} titel="NetworkManager und nmcli">
Auf Desktops und den meisten Servern verwaltet **NetworkManager** das Netz. Er hält **Verbindungsprofile** (connections): Ein Profil sagt, welches **Gerät** (device) es nutzt und wie es eingestellt wird. Ein Gerät hat zu jeder Zeit höchstens ein aktives Profil. Das Werkzeug für die Kommandozeile heißt **nmcli**, jedes Wort darf abgekürzt werden (`nmcli con` = `nmcli connection`, `nmcli d` = `nmcli device`).

| Befehl | Wirkung |
|---|---|
| `nmcli general` | Gesamtzustand: verbunden, Internet erreichbar? |
| `nmcli device` | Geräte, ihr Zustand und ihr aktives Profil |
| `nmcli connection show` | alle Profile |
| `nmcli con show NAME` | alle Einstellungen eines Profils |
| `nmcli con mod NAME ipv4.method manual ipv4.addresses 192.168.1.50/24 ipv4.gateway 192.168.1.1 ipv4.dns 192.168.1.1` | Profil auf feste Adresse umstellen |
| `nmcli con mod NAME ipv4.method auto` | zurück auf DHCP |
| `nmcli con up NAME` / `down NAME` | Profil aktivieren oder trennen |
| `nmcli con add type ethernet ifname enp0s31f6 con-name Messnetz …` | neues Profil anlegen |
| `nmcli radio wifi on` | WLAN einschalten |
| `nmcli dev wifi list` | Funknetze in Reichweite |
| `nmcli dev wifi connect SSID password GEHEIM` | mit einem WLAN verbinden, legt das Profil gleich an |

**Wichtig:** `nmcli con mod` ändert nur das gespeicherte Profil. Wirksam wird es erst mit `nmcli con up`. Profile liegen als Dateien in `/etc/NetworkManager/system-connections/`.

Auf Servern ohne NetworkManager gibt es zwei andere Wege. Debian nutzt klassisch **ifupdown** mit der Datei `/etc/network/interfaces`, die `ifup` und `ifdown` lesen. **systemd-networkd** liest `.network`-Dateien aus `/etc/systemd/network/`, das Werkzeug dazu heißt `networkctl`. Für die Prüfung reicht es, beide zu kennen.
</Karte>

<Merke>Profile statt Geräte: nmcli con mod ändert, nmcli con up wendet an. nmcli device zeigt Geräte, nmcli con show die Profile. WLAN: nmcli dev wifi list, dann connect SSID password PW. Ohne NetworkManager: /etc/network/interfaces mit ifup und ifdown, oder systemd-networkd mit /etc/systemd/network.</Merke>
