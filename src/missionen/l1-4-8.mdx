Ein neuer Kollege fragt: Wo liegt eigentlich die Konfiguration von SSH? Wohin mit dem Tool, das ich selbst übersetzt habe? Und warum findet locate meine Datei nicht? **Deine Mission: Lerne die Ordnung im Verzeichnisbaum und finde jede Datei.** Lernziel 104.7.

## Der Filesystem Hierarchy Standard

<Karte nr={1} titel="Jedes Ding an seinem Ort">
Der **FHS** (Filesystem Hierarchy Standard, aktuell 3.0) legt fest, wofür die Verzeichnisse unter `/` da sind. Fast alle Distributionen halten sich daran.

| Verzeichnis | Inhalt |
|---|---|
| `/bin`, `/sbin` | Programme für alle bzw. für die Verwaltung. Auf Debian 12 Verweise auf `/usr/bin` und `/usr/sbin` |
| `/boot` | Kernel, initramfs, Bootloader |
| `/dev` | Gerätedateien |
| `/etc` | Konfiguration des Systems, nur Textdateien, keine Programme |
| `/home` | Heimatverzeichnisse der Benutzer, `/root` das von root |
| `/lib` | Bibliotheken und Kernelmodule |
| `/media` | automatisch eingehängte Wechselmedien |
| `/mnt` | vorübergehend von Hand eingehängte Dateisysteme |
| `/opt` | in sich geschlossene Zusatzsoftware, etwa `/opt/messsoft` |
| `/proc`, `/sys` | virtuelle Dateisysteme des Kernels |
| `/run` | Laufzeitdaten seit dem Start (PID-Dateien, Sockets), im Arbeitsspeicher |
| `/srv` | Daten, die Dienste anbieten, etwa Webseiten oder Freigaben |
| `/tmp` | temporäre Dateien, oft beim Start geleert |
| `/usr` | der große, nur lesbare Teil: Programme, Bibliotheken, Dokumentation (`/usr/share`) |
| `/usr/local` | selbst installierte Software, die die Paketverwaltung nicht kennt |
| `/var` | veränderliche Daten: `/var/log` Protokolle, `/var/spool` Warteschlangen, `/var/cache`, `/var/lib` Zustand von Programmen |

Merke dir die Unterscheidung: **statisch** (`/usr`, `/opt`) gegen **veränderlich** (`/var`), und **lokal** (`/etc`, `/var`) gegen **teilbar** (`/usr` könnte von mehreren Rechnern gemeinsam benutzt werden).
</Karte>

<Merke>/etc Konfiguration, /var veränderlich, /usr Programme, /usr/local selbst gebaut, /opt Zusatzpakete, /srv Dienstdaten, /run Laufzeit.</Merke>

## Dateien finden

<Karte nr={2} titel="find, locate und die anderen">
- **find** durchsucht das Dateisystem live (Mission 3.6). Gründlich und immer aktuell, aber langsam auf großen Platten.
- **locate** sucht in einer **Datenbank**, die **updatedb** anlegt. Das geht in Millisekunden. Auf Debian 12 liefert das Paket `plocate` beides. updatedb läuft automatisch einmal am Tag. Was danach angelegt wurde, findet locate erst nach `sudo updatedb`. Welche Pfade und Dateisysteme updatedb auslässt, steht in **/etc/updatedb.conf** (`PRUNEPATHS`, `PRUNEFS`). Nützliche Optionen: `-i` ohne Groß/klein, `-c` nur zählen, `-b` nur im Dateinamen suchen.
- **which programm** zeigt den Pfad, unter dem die Shell ein Programm aus PATH starten würde.
- **type name** sagt zusätzlich, ob es ein Alias oder eingebauter Befehl ist.
- **whereis programm** zeigt Programm, Quelltext und Handbuchseiten, unabhängig von PATH.
</Karte>

<Merke>locate: schnell, aber nur so aktuell wie updatedb. find: langsam, aber live. which/type: was die Shell startet. whereis: Programm plus man-Seite.</Merke>

Rechne mit Fragen wie „Wo gehört X hin?“ zu /etc, /var, /usr/local, /opt, /srv, /run und /tmp. Zu locate: updatedb aktualisiert, /etc/updatedb.conf steuert. Zu whereis: findet auch Handbuchseiten.
</Hinweis>
