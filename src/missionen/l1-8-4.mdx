Nach dem Absturz von heute Nacht willst du die Meldungen vor dem Neustart lesen, aber das Journal kennt nur den aktuellen Start. Und `/var/log/messd.log` ist auf 3 GB gewachsen. **Deine Mission: Mach das Journal dauerhaft, finde darin schnell das Richtige und lass alte Logs automatisch verschwinden.** Lernziel 108.2.

## Das Journal

<Karte nr={1} titel="journald, journalctl und journald.conf">
Auf systemd-Systemen nimmt **systemd-journald** zuerst alle Meldungen an: vom Kernel, von Diensten, von syslog-Programmen und aus deren Standardausgabe. Es speichert sie in einem binären Format mit vielen Feldern. Lesen kannst du sie nur mit **journalctl** (Mission 1.5):

| Option | zeigt |
|---|---|
| `-u ssh.service` | eine Unit |
| `-b`, `-b -1`, `--list-boots` | aktueller Start, voriger Start, alle Starts |
| `-p err` | Stufe err und schwerer, wie bei syslog |
| `-t messd` | eine Kennung (das Tag von logger) |
| `-k` | nur Kernelmeldungen |
| `-n 20`, `-r`, `-f` | die letzten 20, die neuesten zuerst, laufend mitlesen |
| `--since "1 hour ago"`, `--until` | einen Zeitraum |

**Wo liegt das Journal?** Gibt es `/var/log/journal`, speichert journald dauerhaft dort. Sonst nur flüchtig in `/run/log/journal`, und beim Neustart ist alles weg. Fest einstellen lässt sich das in **/etc/systemd/journald.conf** mit `Storage=persistent`, `volatile`, `auto` (die Vorgabe, abhängig vom Verzeichnis) oder `none`. Dort steht auch, wie groß es werden darf (`SystemMaxUse=`). Nach einer Änderung: `systemctl restart systemd-journald`.

**Journal eines anderen Systems lesen**: Startet ein Rechner nicht mehr, bootest du ein Rettungssystem, hängst seine Platte ein (etwa unter `/mnt`) und liest dort das Journal mit `journalctl -D /mnt/var/log/journal`. `--root /mnt` sucht das Journal unterhalb einer anderen Wurzel, `--file datei.journal` liest eine einzelne kopierte Datei. Ohne diese Optionen würdest du nur das Journal des Rettungssystems sehen.

Platz: `journalctl --disk-usage` zeigt den Verbrauch, `--vacuum-size=200M` und `--vacuum-time=2weeks` löschen alte Teile. Eigene Meldungen schreibst du mit `logger` oder mit **systemd-cat**: `echo "Sicherung fertig" | systemd-cat -t sicherung -p info`.
</Karte>

<Merke>journalctl -u -b -p -t -k -n -f --since. Dauerhaft mit /var/log/journal oder Storage=persistent in journald.conf. --disk-usage, --vacuum-size. systemd-cat -t tag schreibt hinein. Fremdes Journal: -D Verzeichnis, --root, --file.</Merke>

## Logs rotieren

<Karte nr={2} titel="logrotate">
Logdateien wachsen, bis die Platte voll ist. **logrotate** benennt sie regelmäßig um, komprimiert alte und löscht die ältesten. Gestartet wird es täglich von einem systemd-Timer (oder `/etc/cron.daily`, Mission 7.3). Die Grundeinstellungen stehen in **/etc/logrotate.conf**, die Regeln der Pakete in **/etc/logrotate.d/**:

```
/var/log/messd.log {
    daily
    rotate 7
    compress
    delaycompress
    missingok
    notifempty
    create 640 root adm
    postrotate
        systemctl reload messd
    endscript
}
```

| Option | Wirkung |
|---|---|
| `daily`, `weekly`, `monthly`, `size 100M` | wann rotiert wird |
| `rotate 7` | so viele alte Dateien bleiben, die achte wird gelöscht |
| `compress`, `delaycompress` | alte Dateien mit gzip packen, die jüngste (.1) erst beim nächsten Mal |
| `missingok`, `notifempty` | fehlende Datei ist kein Fehler, leere wird nicht rotiert |
| `create 640 root adm` | neue leere Datei mit diesen Rechten anlegen |
| `postrotate … endscript` | Befehl danach, etwa damit der Dienst die neue Datei öffnet |

Aus `messd.log` wird `messd.log.1`, aus `.1` wird `.2.gz` und so weiter. `logrotate -d datei` zeigt, was passieren würde, ohne etwas zu ändern. `logrotate -f datei` rotiert sofort.
</Karte>

<Merke>/etc/logrotate.conf und /etc/logrotate.d/. rotate N, daily/weekly/size, compress, delaycompress, missingok, notifempty, create, postrotate. -d testet, -f erzwingt.</Merke>
