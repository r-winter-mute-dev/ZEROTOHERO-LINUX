Die Messbox LS-2 steckt am USB-Anschluss von messpc, aber kein Treiber fühlt sich zuständig. Die Labor Mess GmbH liefert ihren Treiber nicht mit dem Kernel aus, sondern als Quellcode in `/usr/src/labsensor-1.2`. **Deine Mission: Bau das Modul einmal von Hand, damit du verstehst, was passiert, und richte es dann mit DKMS so ein, dass es jedes Kernel-Update übersteht.** Lernziel 201.2.

## Ein Modul außerhalb des Kernels

<Karte nr={1} titel="Header, Kbuild, insmod und depmod">
Module, die nicht im Kernel-Quellcode stecken, heißen **out-of-tree**. Grafiktreiber von NVIDIA, WLAN-Treiber mancher Hersteller und die Gasterweiterungen von VirtualBox sind Beispiele. Zum Bauen brauchst du nicht den ganzen Kernel-Quellcode, aber seine **Header** und das Bausystem, genau passend zum Kernel. Auf Debian installiert sie `sudo apt install linux-headers-$(uname -r)`. Sie landen in `/usr/src/linux-headers-VERSION`, und `/lib/modules/VERSION/build` zeigt darauf.

Das Makefile eines solchen Moduls ist kurz. Die Zeile `obj-m += labsensor.o` sagt, was gebaut wird, und `make -C /lib/modules/$(uname -r)/build M=$PWD modules` übergibt die Arbeit an das Bausystem des Kernels. Heraus kommt `labsensor.ko`.

**insmod ./labsensor.ko** lädt genau diese Datei. Es löst keine Abhängigkeiten auf und liest keine Einstellungen aus /etc/modprobe.d. **modprobe labsensor** dagegen sucht das Modul per Namen in `modules.dep`. Darum findet modprobe ein frisch kopiertes Modul erst, nachdem **depmod -a** die Liste neu geschrieben hat. Eigene Module legt man nach `/lib/modules/VERSION/extra/` oder `updates/`. Dateien unter updates/ haben Vorrang vor gleichnamigen unter kernel/.

`modinfo` zeigt in der Zeile **vermagic**, für welchen Kernel ein Modul gebaut ist. Passt sie nicht zum laufenden Kernel, verweigert er das Laden mit `Invalid module format`.

Lädt der Kernel ein fremdes Modul, gilt er als **tainted** (verunreinigt). `cat /proc/sys/kernel/tainted` zeigt eine Bitmaske: 4096 heißt „fremdes Modul“, 8192 „unsigniertes Modul“. Entwickler des Kernels nehmen Fehlerberichte von einem tainted Kernel oft nicht an, weil der Fehler im fremden Code liegen kann.
</Karte>

<Merke>Header: linux-headers-$(uname -r). insmod DATEI: ohne Abhängigkeiten. modprobe NAME: über modules.dep, darum nach dem Kopieren depmod -a. vermagic muss zum Kernel passen.</Merke>

## DKMS

<Karte nr={2} titel="Module, die Kernel-Updates überleben">
Von Hand gebaute Module passen nur zu genau einem Kernel. Nach dem nächsten Kernel-Update ist der Treiber weg, und die Messbox schweigt. **DKMS** (Dynamic Kernel Module Support) löst das: Es kennt den Quellcode und baut das Modul für jeden neu installierten Kernel automatisch nach.

- Der Quellcode liegt in **/usr/src/NAME-VERSION/**, mit einer Datei **dkms.conf**, die Name, Version und das entstehende Modul nennt. `AUTOINSTALL="yes"` sorgt für das automatische Nachbauen.
- `dkms add NAME/VERSION` nimmt das Modul auf, es erscheint in **/var/lib/dkms/**.
- `dkms build NAME/VERSION` baut es für den laufenden Kernel (oder `-k KERNEL`), `dkms install NAME/VERSION` baut, falls nötig, und installiert nach `/lib/modules/KERNEL/updates/dkms/`, samt depmod.
- `dkms status` zeigt jede Kombination aus Modul und Kernel mit „added“, „built“ oder „installed“.
- `dkms autoinstall -k KERNEL` baut alle Module mit AUTOINSTALL für einen Kernel. Genau das ruft der Haken **/etc/kernel/postinst.d/dkms** auf, wenn ein neuer Kernel installiert wird.
- `dkms remove NAME/VERSION --all` entfernt das Modul aus allen Kerneln.

Auch DKMS braucht die Header jedes Kernels. Fehlen sie, meldet es „Your kernel headers for kernel … cannot be found“. Für selbst gebaute Kernel legt `make modules_install` die Verknüpfung `build` an, für Pakete aus `make bindeb-pkg` gibt es ein eigenes linux-headers-Paket.

Ist Secure Boot an, lädt der Kernel nur signierte Module. DKMS kann sie mit einem eigenen Schlüssel signieren, den du einmalig mit `mokutil --import` in die Firmware einträgst. Ohne Secure Boot lädt das Modul auch unsigniert, der Kernel gilt dann aber als tainted.
</Karte>

<Merke>DKMS: Quelle in /usr/src/NAME-VERSION mit dkms.conf. dkms add, dkms install, dkms status. Der Haken in /etc/kernel/postinst.d baut bei jedem neuen Kernel nach. Header nicht vergessen.</Merke>
