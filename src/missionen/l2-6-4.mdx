## Ein Rechner, zwei Netze

<Karte nr={1} titel="Multi-homed">
Ein Rechner mit Anschlüssen in mehreren Netzen heißt **multi-homed**. Für jede Schnittstelle mit Adresse legt der Kernel automatisch eine Route ins direkt angeschlossene Netz an (`proto kernel scope link`). Für alle anderen Ziele entscheidet die Routentabelle.

Neue Hardware findest du so:

```
ip -br link                            # Ist die Schnittstelle da? Zustand DOWN heißt: noch aus
lspci | grep -i ethernet               # Erkennt der Kernel die Karte?
lspci -k                               # Welcher Treiber ist geladen?
dmesg | grep -i e1000e                 # Meldungen des Treibers, auch die Umbenennung
```

Der Treiber meldet die Karte zuerst als `eth1`, udev benennt sie dann nach ihrer Lage auf dem Bus um: `enp3s0` heißt PCI-Bus 3, Slot 0. Dieses **Predictable Network Interface Naming** sorgt dafür, dass der Name nach einem Neustart derselbe bleibt.

Wichtige Regeln für mehrere Netze:

- **Nur eine Standardroute.** Liefern beide Netze per DHCP ein Gateway, entscheidet nur die Metrik, wohin der ganze Verkehr fließt.
- Die **Absenderadresse** eines Pakets hängt von der Route ab: An 10.20.0.5 schickt werkstatt mit 10.20.0.23, ins Internet mit 192.168.1.23. `ip route get ZIEL` zeigt beides.
- **rp_filter** (`net.ipv4.conf.*.rp_filter`) verwirft im strengen Modus Pakete, die auf einer Schnittstelle ankommen, über die die Antwort nicht zurückginge. Asymmetrische Wege fallen dann still aus.
- Für Fälle, in denen die Absenderadresse den Weg bestimmen soll, gibt es **Policy Routing** mit `ip rule` und mehreren Routentabellen.
</Karte>

## Dauerhaft und weiterleitend

<Karte nr={2} titel="interfaces und ip_forward">
Auf Debian ohne NetworkManager steht die Konfiguration in **/etc/network/interfaces**:

```
auto enp3s0
iface enp3s0 inet static
    address 10.20.0.23/16
    up ip route add 10.30.0.0/16 via 10.20.0.1
```

`auto` schaltet die Schnittstelle beim Start ein, `iface … inet static` legt die Adresse fest (`inet dhcp` holt sie per DHCP). Mit `up` oder `post-up` folgen Befehle nach dem Einschalten, mit `down` vor dem Ausschalten. Ein `gateway` gehört nur in die Stanza mit der Standardroute. `ifup enp3s0` und `ifdown enp3s0` wenden die Datei an.

Soll werkstatt Pakete aus dem Büronetz ins Labornetz weiterreichen, muss der Kernel **weiterleiten** dürfen:

```
sudo sysctl -w net.ipv4.ip_forward=1                                   # sofort
echo 'net.ipv4.ip_forward = 1' | sudo tee /etc/sysctl.d/30-ipforward.conf   # dauerhaft
sudo sysctl --system                                                   # alle Dateien neu laden
```

Für IPv6 heißt der Schalter `net.ipv6.conf.all.forwarding`. Damit die Antworten zurückfinden, brauchen die Rechner im Labornetz eine Route ins Büronetz über werkstatt, oder werkstatt maskiert die Absender per NAT. Weiterleiten ist ein Sicherheitsthema: Ein Rechner, der routet, gehört hinter eine Paketfilterregel, die nur erlaubten Verkehr durchlässt.
</Karte>
