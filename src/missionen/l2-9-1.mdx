## Apache 2.4

<Karte nr={1} titel="Ein Programm, zwei Ordnungen">
Apache HTTP Server 2.4 heißt auf Debian **apache2**, auf Red Hat **httpd**. Programm und Direktiven sind gleich, die Dateien sind verschieden geordnet:

| | Debian | Red Hat |
|---|---|---|
| Paket | `apache2` | `httpd` |
| Hauptdatei | `/etc/apache2/apache2.conf` | `/etc/httpd/conf/httpd.conf` |
| Ports | `ports.conf` (`Listen 80`) | in `httpd.conf` |
| Eigene Teile | `sites-available/`, `conf-available/`, `mods-available/`, eingeschaltet per Link in `*-enabled/` | `conf.d/*.conf`, Module in `conf.modules.d/` |
| Steuerung | `apache2ctl`, `a2ensite`, `a2enmod`, `a2enconf` | `apachectl`, `httpd` |
| Protokolle | `/var/log/apache2/access.log`, `error.log` | `/var/log/httpd/access_log`, `error_log` |
| Benutzer | `www-data` | `apache` |
| Dienst | `apache2`, startet sofort | `httpd`, startet erst nach `systemctl enable --now` |

Die Konfiguration besteht aus **Direktiven** (eine pro Zeile, Groß- und Kleinschreibung egal) und **Containern** in spitzen Klammern: `<VirtualHost>`, `<Directory>`, `<Location>`, `<Files>`, `<IfModule>`. Kommentare beginnen mit `#`. `Include` und `IncludeOptional` holen weitere Dateien, Debian holt so die Module, die Ports und alle Seiten.

Apache startet als root, um Port 80 zu öffnen, und lässt die Anfragen von Kindprozessen unter `www-data` oder `apache` bearbeiten.
</Karte>

## Virtuelle Hosts

<Karte nr={2} titel="Mehrere Seiten auf einem Server">
Ein **virtueller Host** ist eine eigene Seite mit eigenem Inhalt und eigenen Protokollen auf demselben Server. Apache entscheidet in zwei Schritten, wer antwortet:

1. **Nach Adresse und Port**: Alle `<VirtualHost>`, deren Adresse zur Verbindung passt. `*:80` passt auf jede Adresse, `192.168.1.23:80` nur auf diese (**IP-basiert**, dafür braucht jede Seite eine eigene Adresse).
2. **Nach Name** (**namensbasiert**): Unter diesen Kandidaten der, dessen `ServerName` oder `ServerAlias` zum Kopf `Host:` der Anfrage passt. Passt keiner, antwortet der **erste**, der Standard-Host.

```
<VirtualHost *:80>
    ServerName www.lab.example.org
    ServerAlias lab.example.org
    DocumentRoot /var/www/www
    ErrorLog ${APACHE_LOG_DIR}/www-error.log
    CustomLog ${APACHE_LOG_DIR}/www-access.log combined
</VirtualHost>
```

Sobald es einen `<VirtualHost *:80>` gibt, beantwortet die Hauptkonfiguration keine Anfragen auf Port 80 mehr, denn der erste virtuelle Host übernimmt. Auf Debian ist das `000-default.conf`, die Ziffern sorgen für die Reihenfolge. `apache2ctl -S` zeigt, welcher Host wofür zuständig ist.

Ohne eigenes `CustomLog` landen Zugriffe auf Debian in `other_vhosts_access.log`, mit dem Namen des Hosts am Zeilenanfang. Das Format `combined` steht in apache2.conf als `LogFormat`.
</Karte>

<Merke>Debian: sites-available schreiben, a2ensite, apache2ctl configtest, systemctl reload apache2. Red Hat: conf.d/NAME.conf, apachectl configtest, systemctl reload httpd. Erst Adresse und Port, dann der Name, sonst der erste Host.</Merke>
