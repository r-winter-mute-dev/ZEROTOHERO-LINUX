Die aktuelle Konfiguration des Messprogramms liegt mal hier, mal dort, und alle Skripte sollen sie unter einem festen Namen finden. Eine Sicherung soll außerdem keinen zusätzlichen Platz kosten. **Deine Mission: Verstehe Inodes und nutze harte und symbolische Links.** Lernziel 104.6.

## Inodes und harte Links

<Karte nr={1} titel="Ein Name ist nur ein Eintrag im Verzeichnis">
Ein Dateisystem speichert zu jeder Datei einen **Inode**: Typ, Rechte, Besitzer, Größe, Zeitstempel und wo die Daten auf der Platte liegen. Nur eins steht nicht darin: der **Name**. Den kennt das **Verzeichnis**: Es ist eine Liste aus Name und Inode-Nummer.

Ein **harter Link** ist einfach ein zweiter Name für denselben Inode: `ln original.txt zweitname.txt`. Beide Namen sind völlig gleichberechtigt. Es gibt kein „Original“ mehr. `ls -li` zeigt vorne die Inode-Nummer (bei beiden gleich) und in der zweiten Spalte den **Linkzähler**. Erst wenn der letzte Name gelöscht ist, gibt das Dateisystem die Daten frei.

Was über einen Namen geändert wird, sieht man unter allen. Auch Rechte und Besitzer gehören zum Inode und gelten für alle Namen.

Grenzen: Harte Links gehen **nicht auf Verzeichnisse** und **nicht über Dateisystemgrenzen**, denn eine Inode-Nummer gilt nur innerhalb eines Dateisystems.

`mv` innerhalb eines Dateisystems ändert nur den Namen, der Inode bleibt. `cp` legt einen neuen Inode an.
</Karte>

<Merke>Name → Inode → Daten. Harter Link = zweiter Name, gleiche Inode-Nummer. Weg erst, wenn der letzte Name weg ist.</Merke>

## Symbolische Links

<Karte nr={2} titel="Ein Wegweiser mit eigenem Inode">
Ein **symbolischer Link** (Symlink, Softlink) ist eine kleine eigene Datei, in der nur ein **Pfad** steht: `ln -s ziel name`. Programme, die ihn öffnen, folgen dem Pfad.

- `ls -l` zeigt ihn als `lrwxrwxrwx … name -> ziel`. Die Rechte des Links sind bedeutungslos, es zählen die des Ziels.
- Er darf auf **Verzeichnisse** zeigen und über **Dateisystemgrenzen** hinweg.
- Wird das Ziel gelöscht oder verschoben, zeigt er **ins Leere** (dangling link).
- Ein relativer Pfad im Link gilt vom Ort des Links aus, nicht vom aktuellen Verzeichnis.

`readlink -f name` zeigt, wo der Link am Ende hinführt. `ln -sf neu name` lässt einen vorhandenen Link auf ein neues Ziel zeigen. Auf jedem Debian findest du Beispiele: `/bin` zeigt auf `usr/bin`, und `/etc/alternatives` ist voller Symlinks.

| | harter Link | symbolischer Link |
|---|---|---|
| eigener Inode | nein | ja |
| auf Verzeichnisse | nein | ja |
| über Dateisysteme | nein | ja |
| Ziel gelöscht | Daten bleiben | Link zeigt ins Leere |
</Karte>

<Merke>ln -s ZIEL NAME. Symlink: eigener Inode, darf auf Ordner und über Grenzen, bricht, wenn das Ziel verschwindet.</Merke>
