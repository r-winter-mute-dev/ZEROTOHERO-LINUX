## SUID und SGID

<Karte nr={1} titel="Programme mit fremden Rechten">
Normalerweise läuft ein Programm mit den Rechten dessen, der es startet. Das **SUID-Bit** (set user ID, Oktal 4000) ändert das: Das Programm läuft mit den Rechten seines **Besitzers**. `passwd` braucht das, weil es als normaler Benutzer `/etc/shadow` ändern muss, und die Datei gehört root. In `ls -l` steht dann ein `s` statt `x` beim Besitzer: `-rwsr-xr-x root root /usr/bin/passwd`. Das **SGID-Bit** (2000) macht dasselbe mit der Gruppe.

Für Angreifer sind solche Dateien Gold wert. Eine Kopie von `bash` mit SUID-Bit, die root gehört, öffnet jedem eine Root-Shell. Darum sucht man regelmäßig danach:

```
find / -perm -4000 -type f 2>/dev/null     # SUID gesetzt
find / -perm -2000 -type f 2>/dev/null     # SGID gesetzt
find / -perm /6000 -type f 2>/dev/null     # SUID oder SGID
```

`-perm -4000` heißt: mindestens dieses Bit ist gesetzt. `-perm /6000` heißt: irgendeines dieser Bits. `2>/dev/null` wirft die Meldungen über nicht lesbare Verzeichnisse weg. Vergleiche das Ergebnis mit einer früheren Liste. Was neu ist und nicht aus einem Paket stammt (`dpkg -S datei`), muss erklärt werden. Entfernt wird das Bit mit `chmod u-s datei` bzw. `chmod g-s datei`.

Bei eingehängten Datenträgern wie USB-Sticks verhindert die Mount-Option **`nosuid`**, dass SUID-Bits darauf überhaupt wirken.
</Karte>

<Merke>SUID 4000: läuft mit den Rechten des Besitzers, s beim Besitzer. SGID 2000: mit den Rechten der Gruppe. find / -perm -4000 sucht SUID, -perm /6000 SUID oder SGID. chmod u-s entfernt es. nosuid beim Einhängen.</Merke>

## Konten und Passwörter

<Karte nr={2} titel="Konten prüfen, sperren und befristen">
Aus Mission 7.2 kennst du `chage`. Für die Sicherheitsprüfung brauchst du diese Befehle:

| Befehl | Wirkung |
|---|---|
| `passwd -S max` | Status: `P` Passwort gesetzt, `L` gesperrt, `NP` kein Passwort |
| `passwd -l max` / `passwd -u max` | Passwort sperren (ein `!` vor dem Hash in /etc/shadow) / entsperren |
| `passwd -e max` | Passwort sofort ablaufen lassen: Beim nächsten Anmelden muss max ein neues setzen |
| `chage -l max` | Ablaufdaten anzeigen |
| `chage -M 90 -W 7 max` | höchstens 90 Tage gültig, 7 Tage vorher warnen |
| `chage -E 2026-12-31 max` | ganzes **Konto** läuft an diesem Tag ab |
| `usermod -L max` / `usermod -U max` | wie passwd -l / -u |
| `usermod -e 2026-12-31 max` | wie chage -E |

**Vorsicht:** Ein gesperrtes Passwort verhindert nur die Anmeldung mit Passwort. Hat max einen SSH-Schlüssel hinterlegt, kommt er weiter herein. Wer ein Konto ganz schließen will, lässt es mit `chage -E 0` ablaufen oder setzt die Shell auf `/usr/sbin/nologin`.
</Karte>

## Offene Ports und offene Dateien

<Karte nr={3} titel="Wer lauscht, wer benutzt was?">
Jeder lauschende Port ist eine Tür. Von **innen** siehst du sie mit dem Programm dahinter:

- `ss -tulpn` (oder das ältere `netstat -tulpn`): alle lauschenden TCP- und UDP-Ports mit Prozess. Den Prozess sieht nur root.
- `lsof -i` listet alle Netzwerkverbindungen und lauschenden Sockets mit Programm, Benutzer und PID. `lsof -i :22` nur Port 22, `lsof -i tcp` nur TCP.
- `fuser -v 22/tcp` zeigt, welcher Prozess Port 22 belegt.

Von **außen** zeigt **nmap**, was ein Angreifer sieht: `nmap localhost`, `nmap 192.168.1.23`, `nmap -p 1-65535 rechner`, `sudo nmap -sU rechner` für UDP. nmap ist meist nicht vorinstalliert (`apt install nmap`). Scanne nur Rechner, für die du zuständig bist. Fremde Netze ohne Erlaubnis zu scannen ist in vielen Ländern strafbar, mindestens aber ein Vertragsbruch beim Provider. Was `ss` von innen zeigt, aber `nmap` von außen nicht sieht, lauscht nur auf `127.0.0.1` oder wird von einer Firewall verdeckt.

**lsof** heißt „list open files“, und für Linux ist fast alles eine Datei. `lsof /mnt/usb` zeigt, wer auf dem Stick arbeitet, `lsof -u max` alle offenen Dateien von max, `lsof -p 3170` die eines Prozesses. **fuser** beantwortet dieselbe Frage kürzer: `fuser -vm /mnt/usb` listet alle Prozesse, die etwas auf diesem Dateisystem geöffnet haben. Die Spalte ZUGR. zeigt `c` für das aktuelle Verzeichnis und `f` für eine offene Datei. `fuser -k` beendet diese Prozesse, zum Beispiel wenn `umount` mit „target is busy“ abbricht.
</Karte>

<Merke>Innen: ss -tulpn, netstat -tulpn, lsof -i, fuser -v PORT/tcp. Außen: nmap rechner, nmap -sU als root. Nur eigene Rechner scannen. lsof /pfad und fuser -vm /pfad: wer belegt was, fuser -k beendet.</Merke>
