Freitagnachmittag. Seit dem Morgen steht in der Mail an root: „DegradedArray event on /dev/md0“. Der Spiegel läuft noch, aber nur noch auf einer Platte. Eine Ersatzplatte steckt schon im Gehäuse. **Deine Mission: Finde die defekte Hälfte, nimm sie aus dem Array, bereite die Ersatzplatte vor, bau den Spiegel neu auf und beschleunige den Wiederaufbau.** Lernziel 204.1.

## Einen Ausfall erkennen

<Karte nr={1} titel="Degradiert, aber nicht tot">
Fällt in einem RAID 1 oder 5 ein Mitglied aus, markiert der Kernel es als **faulty** und arbeitet mit den übrigen weiter. Die Daten sind noch da, aber ohne Schutz: Ein zweiter Ausfall wäre das Ende.

```
$ cat /proc/mdstat
md0 : active raid1 sdd1[1](F) sdc1[0]
      976630488 blocks super 1.2 [2/1] [U_]
```

`(F)` heißt faulty, `[2/1]` zwei Plätze, einer belegt, `[U_]` der zweite fehlt. `mdadm --detail /dev/md0` meldet „State : clean, degraded“ und listet das Gerät unten als faulty. Im Kernel-Protokoll (`dmesg`, `journalctl -k`) stehen die Lesefehler, die zum Ausfall geführt haben.

Damit das nicht erst am Freitag auffällt, läuft **mdadm --monitor** als Dienst (mdmonitor) und schickt bei Ereignissen wie DegradedArray, Fail oder SpareActive eine Mail an die Adresse aus `MAILADDR` in mdadm.conf. Einmal von Hand: `mdadm --monitor --scan --oneshot`.
</Karte>

## Tauschen

<Karte nr={2} titel="Fail, Remove, Partitionieren, Add">
Ein Gerät kann nur aus dem Array genommen werden, wenn es als defekt markiert ist. Hat der Kernel das schon getan, reicht `--remove`. Sonst, etwa vor einem geplanten Tausch, erst `--fail`:

```
sudo mdadm /dev/md0 --fail /dev/sdd1 --remove /dev/sdd1
sudo mdadm --manage /dev/md0 -f /dev/sdd1 -r /dev/sdd1        # gleichwertig
```

Die neue Platte braucht dieselbe Aufteilung wie die gesunde. **sfdisk** kann eine Partitionstabelle als Text ausgeben und wieder einlesen, das ergibt eine exakte Kopie:

```
sudo sfdisk -d /dev/sdc > sdc.tabelle          # Sicherung, gut für später
sudo sfdisk -d /dev/sdc | sudo sfdisk /dev/sde  # direkt übertragen
```

Für GPT-Platten geht das ebenso, oder mit `sgdisk -R /dev/sde /dev/sdc` plus `sgdisk -G /dev/sde` für neue GUIDs. Dann kommt die neue Partition ins Array:

```
sudo mdadm /dev/md0 --add /dev/sde1
```

Der Kernel beginnt sofort mit dem Wiederaufbau, in /proc/mdstat als **recovery** zu sehen. Erst wenn er fertig ist, steht dort wieder [UU].
</Karte>

## Wiederaufbau, Reserve, Wachsen

<Karte nr={3} titel="Schneller, sicherer, größer">
Der Kernel drosselt den Wiederaufbau, damit der Rechner benutzbar bleibt. Die Grenzen stehen in KiB pro Sekunde und je Gerät in:

```
/proc/sys/dev/raid/speed_limit_min    # Standard 1000: so schnell mindestens, auch unter Last
/proc/sys/dev/raid/speed_limit_max    # Standard 200000: höchstens, wenn nichts anderes los ist
sudo sysctl -w dev.raid.speed_limit_min=50000
```

Höheres Minimum heißt: Der Wiederaufbau setzt sich gegen andere Zugriffe durch und das Array ist früher wieder geschützt. Dauerhaft gehört das nach /etc/sysctl.d/.

Eine **Reserveplatte** (spare) springt von selbst ein, sobald ein Mitglied ausfällt. Du gibst sie beim Anlegen mit `--spare-devices=1` an, oder fügst einem vollständigen Array eine Platte mit `--add` hinzu, sie erscheint dann als `(S)`.

Ein RAID 5 lässt sich im laufenden Betrieb um ein Mitglied vergrößern: erst die Platte als Reserve hinzufügen, dann `mdadm --grow /dev/md0 --raid-devices=4`. Der Kernel verteilt die Daten neu (reshape), danach muss noch das Dateisystem wachsen.

Eine ausgebaute Platte, die woanders weiterleben soll, bekommt `mdadm --zero-superblock /dev/sdd1`, sonst versucht mdadm sie beim nächsten Start in ein Array einzubauen.
</Karte>
