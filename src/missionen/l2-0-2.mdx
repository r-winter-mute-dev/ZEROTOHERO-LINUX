In LPIC-1 hat ein Rechner gereicht. Für LPIC-2 brauchst du ein Netz: Ein Nameserver ist sinnlos, wenn niemand ihn fragt, und eine Firewall, wenn nichts durch sie hindurchgeht. **Deine Mission: Baue ein kleines Firmennetz aus drei virtuellen Maschinen, mit einem Router, der den Weg ins Internet freigibt.**

## Der Plan

<Karte nr={1} titel="Drei Maschinen, ein eigenes Netz">
```
         Internet
            │
   ┌────────┴────────┐   NAT-Adapter von VirtualBox (enp0s3, Adresse per DHCP)
   │  gw    (Router) │
   └────────┬────────┘   internes Netz „firma“ (enp0s8) 192.168.50.1
            │
     ┌──────┴───────┐
 ┌───┴────┐    ┌────┴─────┐
 │ srv1   │    │ client1  │
 │ .10    │    │ .20      │
 └────────┘    └──────────┘
```

- **gw** ist der Router: Debian 12 ohne Desktop, 1 GB RAM. Er hat zwei Netzwerkadapter: Adapter 1 hängt am **NAT** von VirtualBox und kommt damit ins Internet, Adapter 2 hängt im **internen Netz** mit dem Namen `firma`.
- **srv1** ist der Server: Debian 12 ohne Desktop, 2 GB RAM, ein Adapter im internen Netz `firma`. Gib ihm gleich **drei zusätzliche virtuelle Platten** zu je 2 GB. Die brauchst du in Akt 5 für RAID und LVM.
- **client1** ist der Arbeitsplatz: Debian 12 mit Xfce oder AlmaLinux 9, 2 GB RAM, ein Adapter im internen Netz.

Ein internes Netz in VirtualBox ist wie ein Switch, an dem nur deine VMs hängen. Es gibt dort keinen DHCP-Server und keinen Weg nach draußen. Den Weg baust du selbst, mit gw. Andere Programme nennen das anders, etwa „isoliertes Netz“ oder „Host Only“. Wichtig ist nur: ein Netz, in dem allein deine VMs hängen. Auch die Namen der Schnittstellen können dann anders lauten, `ip -br link` zeigt sie dir.
</Karte>

## Den Router einrichten

<Karte nr={2} titel="Weiterleiten und maskieren">
Ein Linux-Rechner leitet Pakete zwischen seinen Schnittstellen nur weiter, wenn man es ihm erlaubt. Das steuert die Kernel-Einstellung **`net.ipv4.ip_forward`**. Damit das dauerhaft gilt, kommt sie in eine Datei unter `/etc/sysctl.d/`:

```
# /etc/sysctl.d/90-router.conf
net.ipv4.ip_forward = 1
```

`sudo sysctl --system` liest alle diese Dateien sofort ein.

Weiterleiten reicht noch nicht. Die Adressen 192.168.50.x sind privat, das Internet kennt keinen Rückweg dorthin. Darum ersetzt der Router beim Hinausgehen die Absenderadresse durch seine eigene und merkt sich die Verbindung (**NAT**, hier in der Form **Masquerading**). Das erledigt **nftables**, die Firewall des Kernels:

```
#!/usr/sbin/nft -f
# /etc/nftables.conf auf gw
flush ruleset

table ip nat {
    chain postrouting {
        type nat hook postrouting priority srcnat; policy accept;
        oifname "enp0s3" masquerade
    }
}
```

`sudo systemctl enable --now nftables` lädt die Regeln jetzt und bei jedem Start. Die feste Adresse für enp0s8 trägst du in `/etc/network/interfaces` ein, siehe Spickzettel. Mehr über Router und Firewall kommt in Akt 13.
</Karte>

<Merke>ip_forward = 1 in /etc/sysctl.d/, sysctl --system. NAT: nftables-Regel masquerade für die Schnittstelle nach draußen, systemctl enable --now nftables.</Merke>
