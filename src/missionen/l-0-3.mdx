Ein Server braucht ein Betriebssystem. Bevor du den ersten Befehl tippst, brauchst du also ein eigenes Linux, eines, das du verändern und auch kaputt machen darfst. **Deine Mission: Richte Arch Linux ein und melde dich als normaler Benutzer an.**

**Du brauchst:** deinen Rechner, eine Internetverbindung und etwa eine Stunde Zeit. Mit WSL geht es meist schneller.

## Theorie

<Karte nr={1} titel="Was eine Distribution ist">
Streng genommen ist **Linux** nur der **Kernel**: das Programm, das zwischen Hardware und allen anderen Programmen vermittelt. Damit man damit arbeiten kann, braucht es noch eine Shell, Werkzeuge wie `ls` und eine **Paketverwaltung**, die Software installiert. Dieses Gesamtpaket heißt **Distribution**. Arch, Debian, Ubuntu und Fedora sind Distributionen. Sie teilen sich den Kernel und die meisten Werkzeuge.
</Karte>

<Merke>Linux ist der Kernel. Eine Distribution packt Kernel, Werkzeuge und Paketverwaltung zusammen.</Merke>

<Karte nr={2} titel="WSL oder virtuelle Maschine">
Eine **virtuelle Maschine (VM)** ist ein simulierter Computer mit eigener Festplatte, auf dem ein komplettes Linux bootet. **WSL** (Windows Subsystem for Linux) ist leichter: Windows startet einen echten Linux-Kernel im Hintergrund, und du bekommst sofort ein Terminal. WSL ist schneller eingerichtet. Eine VM ist näher an einem echten Server, weil sie selbst bootet und ein eigenes Netzwerk hat. Für Akt 0 bis 5 reicht WSL locker. Ab Akt 6 (Netzwerk, SSH, Firewall) ist eine VM besser.
</Karte>

<Merke>WSL: schnell und leicht. VM: ein ganzer Rechner, näher am echten Server.</Merke>

<Hinweis titel="Mac mit Apple-Chip (M1 und neuer)">
Arch Linux gibt es offiziell nur für Intel- und AMD-Prozessoren (x86_64). Auf einem Mac mit Apple-Chip läuft es nur emuliert, zum Beispiel mit UTM, und dann sehr langsam [Trainingswissen, nicht geprüft]. Mach bis auf Weiteres im Simulator weiter und setz oben den Haken „ohne Linux“. Auf einem Mac mit Intel-Chip funktioniert Weg B.
</Hinweis>

## Weg A: WSL unter Windows

Öffne **PowerShell** über das Startmenü. Normale Rechte reichen, Windows fragt nach, wenn es Adminrechte braucht.

  'Arch starten: <code>wsl -d archlinux</code>. Der Prompt endet mit <code>#</code>, du bist also root (Mission 0.2, Regel 2). Das ändern wir jetzt.',

  'Bei <code>passwd</code> zweimal ein Passwort eingeben. Es erscheinen keine Sternchen, das ist normal.',
  'Mit <code>exit</code> zurück zu PowerShell, dann <code>wsl --terminate archlinux</code> und wieder <code>wsl -d archlinux</code>.',

Die Ersteinrichtung, Zeile für Zeile:

```bash
pacman -Syu                                   # 1. System aktualisieren
pacman -S --needed sudo nano                  # 2. sudo und einen Editor installieren
useradd -m -G wheel mia                       # 3. Benutzer mia anlegen, Gruppe wheel
passwd mia                                    # 4. Passwort für mia setzen
echo '%wheel ALL=(ALL:ALL) ALL' > /etc/sudoers.d/wheel   # 5. Gruppe wheel darf sudo
chmod 440 /etc/sudoers.d/wheel                # 6. Datei nur lesbar machen
visudo -c                                     # 7. Prüfen: muss "parsed OK" melden
printf '[user]\ndefault=mia\n' >> /etc/wsl.conf          # 8. WSL startet künftig als mia
```

| Zeile | Was passiert | Ausführlich in |
| --- | --- | --- |
| 1 | `pacman` ist die Paketverwaltung von Arch. `-Syu` holt die neuesten Paketlisten und aktualisiert alles. Bei Fragen mit Enter bestätigen. | Mission 5.3 |
| 2 | Installiert `sudo` (Adminrechte auf Zeit) und den einfachen Editor `nano`. | Mission 5.2 |
| 3 | Legt den Benutzer an. `-m` erstellt seinen Heimatordner, `-G wheel` steckt ihn in die Gruppe der Admins. | Mission 3.6 |
| 4 | Setzt das Passwort. Merk es dir gut, sudo fragt danach. | Mission 3.6 |
| 5 bis 7 | Erlaubt der Gruppe wheel, sudo zu benutzen, und prüft, ob die Datei fehlerfrei ist. | Mission 3.5 |
| 8 | Schreibt in die WSL-Einstellungen, dass Arch als dein Benutzer startet statt als root. | – |

<Hinweis titel="Eine Ausnahme von Regel 4">
Du führst hier Befehle aus, die du noch nicht ganz verstehst. Das ist die einzige Stelle im Kurs, an der das nötig ist. Jede Zeile ist oben erklärt und wird später ausführlich behandelt.
</Hinweis>

## Sicherung anlegen

Dein frisches System ist der perfekte Stand, um im Notfall zurückzukehren (Mission 0.2, Regel 6).

- **VM:** Maschine ausschalten, in VirtualBox die Maschine auswählen, *Snapshots* und *Erstellen*. Name: „Frisch installiert“.
- **WSL:** In PowerShell `wsl --export archlinux $HOME\arch-frisch.tar`. Zurück geht es später mit `wsl --import`.

## Typische Fehler

| Symptom | Wahrscheinliche Ursache | Lösung |
| --- | --- | --- |
| `wsl --install` meldet, die Distribution gebe es nicht | WSL ist veraltet | In PowerShell `wsl --update`, dann erneut versuchen |
| `pacman -Syu` meldet `signature … is unknown trust` | Die Schlüssel der Paketverwaltung sind noch nicht eingerichtet | `pacman-key --init`, dann `pacman-key --populate archlinux`, dann noch einmal `pacman -Syu` |
| Nach dem Neustart von WSL wieder `#` im Prompt | Zeile 8 fehlt oder enthält einen Tippfehler | `cat /etc/wsl.conf` muss `[user]` und darunter `default=deinname` zeigen |
| VM bootet nur schwarz oder der Installer bricht beim Bootloader ab | EFI ist nicht aktiviert | VM ausschalten, unter *System* EFI aktivieren, Installation wiederholen |
| In der VM sind Y und Z vertauscht | US-Tastaturbelegung | `loadkeys de-latin1`. Im installierten System übernimmt archinstall die gewählte Belegung |

<details>
<summary><strong>Vertiefung: Warum heißt die Admin-Gruppe „wheel“?</strong></summary>

Der Name stammt aus alten Unix-Systemen der 1970er Jahre und spielt auf „big wheel“ an, englisch für eine wichtige Person. Viele Distributionen nennen die Gruppe heute `sudo`, Arch bleibt beim alten Namen [Trainingswissen].
</details>
