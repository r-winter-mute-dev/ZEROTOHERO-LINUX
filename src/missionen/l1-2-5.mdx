dpkg arbeitet mit Dateien, die du schon hast. Meistens willst du aber einfach sagen „installier htop“, und der Rest soll von selbst gehen: Paket finden, herunterladen, Abhängigkeiten auflösen. Das ist die Aufgabe von **apt**. **Deine Mission: Such, installiere und entferne Software aus den Debian-Repositories.** Lernziel 102.4.

## Die Quellen

<Karte nr={1} titel="sources.list">
apt holt Pakete aus **Repositories**, Servern mit Tausenden Paketen. Welche, steht in **/etc/apt/sources.list** und in Dateien unter **/etc/apt/sources.list.d/**:

```
deb http://deb.debian.org/debian bookworm main non-free-firmware
```

- **deb** heißt fertige Pakete, **deb-src** wäre Quellcode.
- Dann die **Adresse** des Servers,
- die **Version** der Distribution (bookworm ist Debian 12),
- und die **Bereiche** (main, contrib, non-free, non-free-firmware).

Neuere Systeme nutzen dafür manchmal das Format `*.sources` unter sources.list.d. Der Inhalt ist derselbe, nur anders geschrieben.

`apt-get update` lädt die **Paketlisten** aller Quellen neu. Es installiert nichts. Danach weiß apt, welche Versionen es gibt.
</Karte>

<Merke>sources.list sagt, woher. apt-get update holt die Listen, installiert aber nichts.</Merke>

<Karte nr={2} titel="apt-cache: suchen und nachschauen">
| Befehl | Zeigt |
| --- | --- |
| `apt-cache search begriff` | Pakete, deren Name oder Beschreibung passt |
| `apt-cache show htop` | Version, Größe, Abhängigkeiten, Beschreibung |
| `apt-cache depends htop` | wovon htop abhängt |
| `apt-cache rdepends htop` | welche Pakete von htop abhängen |
| `apt-cache policy htop` | installierte und verfügbare Version, aus welcher Quelle |

`apt-cache` braucht keine Root-Rechte, es liest nur.
</Karte>

## Installieren, aktualisieren, entfernen

<Karte nr={3} titel="apt-get">
| Befehl | Tut |
| --- | --- |
| `apt-get install htop` | installiert htop samt Abhängigkeiten |
| `apt-get remove htop` | entfernt htop, Konfiguration bleibt |
| `apt-get purge htop` | entfernt htop samt Konfiguration |
| `apt-get autoremove` | entfernt Abhängigkeiten, die niemand mehr braucht |
| `apt-get upgrade` | aktualisiert alle Pakete, installiert und entfernt dabei **nie** etwas |
| `apt-get dist-upgrade` | aktualisiert auch dann, wenn dafür Pakete hinzukommen oder wegfallen |
| `apt-get download htop` | lädt nur die .deb-Datei herunter |

Kommen zusätzliche Pakete dazu, fragt apt-get „Do you want to continue? [Y/n]“. Der Großbuchstabe ist die Vorgabe: Enter heißt hier Ja. Mit `-y` fällt die Frage weg, praktisch in Skripten. Heruntergeladene Pakete liegen in `/var/cache/apt/archives`.
</Karte>

<Karte nr={4} titel="apt, das neuere Werkzeug">
`apt` fasst die wichtigsten Befehle von apt-get und apt-cache zusammen (`apt install`, `apt search`, `apt show`) und zeigt einen Fortschrittsbalken. Für die Arbeit am Terminal ist es bequemer. In Skripten nimmt man weiter apt-get, weil sich die Ausgabe von apt ändern darf. Das Lernziel verlangt für apt nur, dass du es kennst.
</Karte>

<Merke>upgrade nimmt nie etwas weg, dist-upgrade schon. apt ist bequem, apt-get für Skripte.</Merke>

<Hinweis titel="dpkg -S oder apt-file?">
Beide finden das Paket zu einer Datei. dpkg -S sucht nur unter den installierten Paketen, apt-file search in allen Paketen der Quellen. Steht in der Prüfung „auch wenn es nicht installiert ist“, ist apt-file gemeint.
</Hinweis>
