Die Kollegen beschweren sich, dass Kopieren auf die große Platte die ganze Maschine ausbremst. **Deine Mission: Lies aus, was die Geräte können, stell den Schreibcache und den I/O-Scheduler passend ein und sorg dafür, dass die SSD regelmäßig getrimmt wird.** Lernziel 204.2.

## Vom Controller zum Gerätenamen

<Karte nr={1} titel="IDE, SATA, AHCI, NVMe">
Früher hingen Platten am parallelen **IDE**-Bus (auch PATA, ATA), der alte Treiber nannte sie /dev/hda, /dev/hdb. Ob die Platte per **DMA** (Direct Memory Access) Daten direkt in den Speicher schreiben durfte oder jedes Byte über den Prozessor ging (PIO), war damals eine echte Einstellung: `hdparm -d1 /dev/hda`.

Heute laufen SATA-Platten über den Treiber **libata**, der sie wie SCSI-Geräte behandelt. Darum heißen SATA-, SAS-, USB- und iSCSI-Platten alle /dev/sd*. Der SATA-Controller arbeitet im Modus **AHCI** (Advanced Host Controller Interface), dem Standard, der Native Command Queuing und Hotplug kann. DMA ist dort immer an.

**NVMe**-SSDs hängen direkt am PCI-Express-Bus und haben ein eigenes, schlankes Protokoll mit vielen parallelen Warteschlangen. Sie heißen /dev/nvme0n1: Controller 0, Namespace 1, Partitionen p1, p2.

Jeder Controller meldet fertige Aufträge über einen **Interrupt**. Welche es gibt und wie oft sie feuern, steht in /proc/interrupts. Bei NVMe siehst du dort oft eine Zeile pro Warteschlange und Prozessorkern.
</Karte>

## hdparm, sdparm, nvme

<Karte nr={2} titel="Fragen und einstellen">
```
sudo hdparm -I /dev/sdc       # alles, was die Platte über sich sagt: Modell, Sektoren, Drehzahl, TRIM, Cache
sudo hdparm -tT /dev/sdc      # Lesetempo aus dem Cache (-T) und von der Platte (-t)
sudo hdparm -W0 /dev/sdc      # Schreibcache aus (-W1 an, -W allein zeigt den Zustand)
sudo hdparm -S 120 /dev/sdc   # nach 120 × 5 s = 10 min Leerlauf in den Standby
sudo hdparm -C /dev/sdc       # Zustand: active/idle oder standby
```

hdparm spricht ATA-Befehle. Für SCSI-Geräte, SAS, USB und iSCSI gibt es **sdparm** (Mode Pages, VPD-Kennungen, `--get=WCE` für den Schreibcache). Für NVMe gibt es **nvme-cli**:

```
sudo nvme list                    # alle NVMe-Geräte mit Modell, Firmware, Belegung
sudo nvme id-ctrl /dev/nvme0      # Fähigkeiten des Controllers
sudo nvme smart-log /dev/nvme0    # Temperatur, Abnutzung (percentage_used), Fehler
```

Ein abgeschalteter Schreibcache macht Schreiben langsamer, aber sicherer bei Stromausfall ohne USV. Einstellungen von hdparm gelten bis zum nächsten Neustart. Dauerhaft gehören sie auf Debian in /etc/hdparm.conf oder in eine udev-Regel.
</Karte>

## Scheduler und TRIM

<Karte nr={3} titel="Wer zuerst darf, und was frei ist">
Der **I/O-Scheduler** entscheidet, in welcher Reihenfolge Lese- und Schreibaufträge an ein Gerät gehen. Jedes Blockgerät hat seinen eigenen:

```
$ cat /sys/block/sdc/queue/scheduler
[mq-deadline] kyber bfq none
$ echo bfq | sudo tee /sys/block/sdc/queue/scheduler
```

Die eckigen Klammern zeigen den aktiven. **mq-deadline** sortiert und verhindert, dass Aufträge verhungern. **bfq** verteilt die Bandbreite fair auf Prozesse, gut für drehende Platten an Arbeitsplätzen. **kyber** zielt auf niedrige Latenz bei schnellen Geräten, **none** reicht alles direkt durch, üblich bei NVMe. Ob ein Gerät dreht, verrät /sys/block/sdc/queue/rotational (1 ja, 0 nein). Dauerhaft setzt man den Scheduler per udev-Regel.

SSDs müssen wissen, welche Blöcke das Dateisystem nicht mehr braucht, sonst werden sie mit der Zeit langsam. Das teilt ihnen **TRIM** (bei SCSI: UNMAP, allgemein discard) mit:

```
lsblk -D                    # DISC-MAX größer als 0B: Gerät kann discard
sudo fstrim -v /            # einmal für ein Dateisystem
sudo fstrim -av             # für alle eingehängten, die es können
systemctl status fstrim.timer   # Debian, Ubuntu und Red Hat trimmen so wöchentlich
```

Alternativ trimmt die Einhängeoption `discard` sofort bei jedem Löschen, was auf manchen SSDs bremst. `tune2fs -o discard /dev/…` speichert sie als Standardoption im ext4. Über **sysctl** stellst du Kernel-Werte wie `vm.dirty_ratio` (ab welchem Anteil schmutziger Seiten Schreiber selbst warten müssen) oder `dev.raid.speed_limit_min` ein.
</Karte>
