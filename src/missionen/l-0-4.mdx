Dein Server wird keinen Bildschirm mit Fenstern haben, keine Maus und keine Menüs. Alles, was du ihm sagen willst, tippst du ein. Das Programm, das deine Eingaben entgegennimmt, heißt **Shell**, bei Arch ist das standardmäßig **bash**. Das Fenster drumherum ist das **Terminal**. **Deine Mission: Lerne, mit der Shell zu sprechen.**

## Theorie

<Karte nr={1} titel="Der Prompt">
Bevor du etwas tippst, zeigt die Shell den **Prompt**: `[hero@archbox ~]$`. Er verrät dir drei Dinge. Vor dem `@` steht dein **Benutzername** (hier `hero`), dahinter der Name des **Rechners** (`archbox`). Danach kommt der Ordner, in dem du gerade bist. Die Tilde `~` steht für deinen **Heimatordner**, deinen persönlichen Bereich. Das letzte Zeichen kennst du aus Mission 0.2: `$` für normale Benutzer, `#` für root.
</Karte>

<Merke>Der Prompt zeigt: wer, auf welchem Rechner, in welchem Ordner. ~ ist dein Heimatordner.</Merke>

<Karte nr={2} titel="Befehl, Option, Argument">
Jede Eingabe hat denselben Aufbau, getrennt durch Leerzeichen: zuerst der **Befehl**, also das Programm. Dann **Optionen**, meist mit einem Minus davor, sie ändern das Verhalten. Zuletzt **Argumente**: worauf der Befehl wirken soll. In `ls -l /etc` ist `ls` der Befehl (Inhalt auflisten), `-l` die Option (ausführlich) und `/etc` das Argument (dieser Ordner). Linux unterscheidet **Groß- und Kleinschreibung**: `ls` ist nicht `LS`.
</Karte>

<Merke>befehl -option argument. Leerzeichen trennen, Groß und klein sind verschieden.</Merke>

<Karte nr={3} titel="Tasten, die Zeit sparen">
Niemand tippt alles aus. **Tab** vervollständigt: Tippst du `cat no` und drückst Tab, ergänzt die Shell `notiz.txt`, wenn es nur eine passende Datei gibt. Gibt es mehrere, zeigt zweimal Tab die Auswahl. Mit **↑** holst du frühere Befehle zurück. **Strg+C** bricht ab, was gerade läuft oder halb getippt ist. **Strg+L** leert den Bildschirm. Kopieren und Einfügen geht in den meisten Terminals mit **Strg+Umschalt+C** und **Strg+Umschalt+V**, weil Strg+C schon belegt ist.

<Karte nr={4} titel="Fehlermeldungen lesen">
Fehler sind im Terminal normal und nützlich. Die Meldung `bash: Whoami: command not found` hat einen festen Aufbau: **Wer** meldet sich (`bash`), **was** war betroffen (`Whoami`), **warum** ging es nicht (`command not found`, Befehl nicht gefunden). Fast alle Programme melden Fehler nach diesem Muster, meist auf Englisch. Lies immer die ganze Meldung, bevor du etwas änderst. Die Ursache steht oft wörtlich darin.
</Karte>

<Merke>Fehlermeldungen lesen: wer, was, warum. Die Ursache steht meist schon da.</Merke>

## Im echten Terminal

Jetzt in deinem eigenen Arch. Der Befehl unten enthält einen Code, der nur für dich erzeugt wurde. `echo` gibt ihn aus, der senkrechte Strich `|` reicht die Ausgabe weiter, und `sha256sum` berechnet daraus eine Prüfsumme, eine Art Fingerabdruck. Den Strich findest du auf deutschen Tastaturen mit <kbd>AltGr</kbd>+<kbd>&lt;</kbd>. Was `|` genau tut, lernst du in Mission 2.4.

<Nachweis id="echt" befehl="echo {code} | sha256sum" muster={['^{sha}\\s+-\\s*$']} hilfe={[
  { muster: 'is not recognized|wird nicht als|CommandNotFoundException|nicht erkannt', text: 'Das kam von Windows. Öffne zuerst dein Arch (wsl -d archlinux) und gib den Befehl dort ein.' },
  { muster: '^{code}\\s*$', text: 'Das ist nur die Ausgabe von echo. Hinter den Code gehört noch | sha256sum.' },
  { muster: '^[0-9a-f]{64}\\s+-', text: 'Das ist eine Prüfsumme, aber nicht die erwartete. Kopiere den Befehl genau so, mit deinem Code und ohne Anführungszeichen drumherum.' },
]} />

<Hinweis titel="Warum eine Prüfsumme?">
Schon ein einziges anderes Zeichen ergibt eine völlig andere Prüfsumme. Deshalb kann die Seite erkennen, ob die Ausgabe wirklich zu deinem Code gehört, ohne dass irgendetwas verschickt wird. Prüfsummen begegnen dir wieder, wenn du heruntergeladene Dateien prüfst.
</Hinweis>

## Typische Fehler

| Symptom | Ursache | Lösung |
| --- | --- | --- |
| `command not found` | Tippfehler oder Großbuchstaben | Befehl klein und genau so tippen. Tab hilft |
| Es passiert gar nichts, kein neuer Prompt | Ein Programm wartet auf Eingabe, oft ein offenes Anführungszeichen (`>` am Zeilenanfang) | Strg+C |
| Strg+V fügt nichts ein, sondern zeigt `^V` | Im Terminal ist Strg+V belegt | Strg+Umschalt+V oder Rechtsklick, Einfügen |
| `^[[A` erscheint statt des letzten Befehls | Du bist in einem Programm, das keine Pfeiltasten kennt | Strg+C, dann neu versuchen |

<details>
<summary><strong>Vertiefung: Shell, Terminal, Konsole</strong></summary>

Die Begriffe werden oft durcheinander benutzt. Genau genommen ist das **Terminal** das Fenster, das Tastendrücke annimmt und Text anzeigt. Früher war das ein eigenes Gerät mit Bildschirm und Tastatur. Die **Shell** ist das Programm darin, das deine Zeile liest, versteht und Programme startet. Es gibt mehrere Shells, zum Beispiel bash, zsh und fish. Der Kurs nutzt bash, weil sie auf fast jedem Linux-Server vorhanden ist. Mit **Konsole** meint man meist den Textbildschirm direkt am Rechner, ohne grafische Oberfläche, so wie in deiner VM.
</details>
