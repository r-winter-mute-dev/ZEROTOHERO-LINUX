In Mission 1.5 hast du GRUB für einen einzigen Start etwas mitgegeben. Jetzt änderst du ihn dauerhaft. Dabei gibt es zwei Generationen, und die Prüfung fragt beide ab: das alte **GRUB Legacy** und das heutige **GRUB 2**. **Deine Mission: Stell GRUB 2 auf „werkstatt“ um und lies eine Konfiguration von GRUB Legacy.** Lernziel 102.2.

## GRUB Legacy

<Karte nr={1} titel="Eine Datei, von Hand gepflegt">
GRUB Legacy (Version 0.97) liest beim Start genau eine Datei, die du direkt bearbeitest: **/boot/grub/menu.lst** (Debian, SUSE) oder **/boot/grub/grub.conf** (Red Hat). So sieht ein Eintrag aus:

```
default 0
timeout 5
title Debian
    root (hd0,0)
    kernel /vmlinuz root=/dev/sda2 ro quiet
    initrd /initrd.img
```

Wichtig ist die Zählweise: **Platten und Partitionen zählen ab 0.** `(hd0,0)` ist die erste Partition der ersten Platte. `default 0` startet den ersten Eintrag. Installiert wird GRUB Legacy mit `grub-install /dev/sda` oder in der GRUB-Shell mit `setup (hd0)`.
</Karte>

<Merke>GRUB Legacy: menu.lst oder grub.conf von Hand bearbeiten. (hd0,0) = erste Platte, erste Partition.</Merke>

## GRUB 2

<Karte nr={2} titel="Erzeugt, nicht bearbeitet">
GRUB 2 liest **/boot/grub/grub.cfg** (bei Red Hat **/boot/grub2/grub.cfg**). Diese Datei bearbeitest du **nicht**: Sie wird aus Vorlagen erzeugt und beim nächsten Kernel-Update überschrieben. Stattdessen änderst du

- **/etc/default/grub** für Einstellungen wie `GRUB_TIMEOUT`, `GRUB_DEFAULT` und `GRUB_CMDLINE_LINUX_DEFAULT` (Kernelparameter),
- **/etc/grub.d/** für die Skripte, die die Einträge erzeugen. Eigene Einträge gehören in `40_custom`.

Danach erzeugst du die Datei neu: **grub-mkconfig -o /boot/grub/grub.cfg**. Unter Debian und Ubuntu macht `update-grub` genau das. Unter Red Hat heißt das Programm `grub2-mkconfig`.

GRUB 2 zählt **Platten ab 0, Partitionen ab 1**: `(hd0,1)` oder ausführlicher `(hd0,gpt1)` ist die erste Partition der ersten Platte.
</Karte>

<Merke>GRUB 2: /etc/default/grub ändern, dann grub-mkconfig -o /boot/grub/grub.cfg. grub.cfg nie von Hand.</Merke>

Die häufigste Fehlerquelle: /etc/default/grub geändert, grub-mkconfig vergessen. Die zweithäufigste: grub.cfg direkt bearbeitet, und nach dem nächsten Kernel-Update ist alles weg.

## Rückfalloptionen und Bedienung

<Karte nr={3} titel="Wenn der normale Start scheitert">
Das Lernziel verlangt „alternative Boot-Orte und Rückfalloptionen“. Gemeint sind:

- **Ältere Kernel** bleiben installiert. GRUB 2 legt sie unter „Advanced options“ ab. Startet der neue Kernel nicht, wählst du den alten.
- **Recovery mode**: Ein Eintrag, der in den Einzelbenutzermodus startet.
- **Ein anderes Medium**: ein Live- oder Rettungssystem auf USB-Stick, mit dem du das installierte System reparierst und GRUB neu installierst.
- **Andere Betriebssysteme** findet das Skript `os-prober` und nimmt sie ins Menü auf.
</Karte>

<Karte nr={4} titel="Mit GRUB reden">
Im Menü kennst du schon **e** (Eintrag bearbeiten). Mit **c** öffnest du die **GRUB-Kommandozeile**, mit **Esc** geht es zurück. Auf der Kommandozeile kannst du ein System auch von Hand starten, wenn die Konfiguration kaputt ist:

```
grub> ls
(hd0) (hd0,gpt1) (hd0,gpt2) (hd0,gpt3)
grub> set root=(hd0,gpt2)
grub> linux /boot/vmlinuz-6.1.0-27-amd64 root=/dev/nvme0n1p2 ro
grub> initrd /boot/initrd.img-6.1.0-27-amd64
grub> boot
```

Neu **installiert** wird GRUB mit `grub-install`: auf BIOS-Rechnern mit dem Ziel `/dev/sda`, also in den MBR der Platte, auf UEFI-Rechnern in die ESP, etwa mit `--efi-directory=/boot/efi`.
</Karte>

<Merke>Rückfall: alter Kernel, recovery mode, Rettungs-USB. Im Menü: e bearbeiten, c Kommandozeile.</Merke>
