Morgen tauscht die Haustechnik den Switch im Labor, das Kabelnetz ist dann für ein paar Stunden weg. werkstatt hat eine WLAN-Karte, die aber nie benutzt wurde: NetworkManager ist für sie abgeschaltet, und irgendwer hat den Funk blockiert. **Deine Mission: Gib die WLAN-Karte frei, finde das Labor-WLAN, verbinde dich ohne NetworkManager per wpa_supplicant (Passwort: Werkstatt2026) und hol dir eine Adresse.** Lernziel 205.1.

## Funk ein, Funk aus

<Karte nr={1} titel="rfkill und die Werkzeuge für WLAN">
Bevor eine WLAN-Karte senden darf, prüft der Kernel den **rfkill**-Zustand. Ein **Soft-Block** ist ein Software-Schalter, etwa durch eine Funktionstaste, den Flugmodus oder `rfkill block`. Ein **Hard-Block** kommt von einem echten Schalter oder dem BIOS und lässt sich aus Linux heraus nicht aufheben.

```
$ rfkill
ID TYPE      DEVICE      SOFT      HARD
 1 wlan      phy0     blocked unblocked
$ sudo rfkill unblock wifi
```

Solange ein Block besteht, scheitern `ip link set wlp2s0 up` und jeder Scan mit „Operation not possible due to RF-kill“.

Für WLAN gibt es zwei Werkzeugfamilien:

- **iw** (aktuell, nl80211): `iw dev`, `iw dev wlp2s0 link`, `iw dev wlp2s0 scan`, `iw list`, `iw reg get`.
- **wireless-tools** (veraltet, Wireless Extensions): `iwconfig` zeigt und setzt ESSID, Modus und Sendeleistung, `iwlist wlp2s0 scan` sucht Netze. Auf vielen Systemen nicht mehr installiert.

Scannen braucht root, ohne root zeigen die Werkzeuge höchstens zwischengespeicherte Ergebnisse.
</Karte>

## Anmelden mit wpa_supplicant

<Karte nr={2} titel="Vom Passwort zum PSK">
`iw dev wlp2s0 connect SSID` verbindet nur mit offenen Netzen oder WEP. Für **WPA2** und **WPA3** braucht es **wpa_supplicant**. Der Dienst handelt mit dem Access Point die Schlüssel aus und hält die Verbindung.

Die Konfiguration erzeugt `wpa_passphrase`. Es rechnet aus Passwort und SSID den 256-Bit-**PSK** (PBKDF2 mit 4096 Runden):

```
$ wpa_passphrase Labor-WLAN Werkstatt2026 | sudo tee /etc/wpa_supplicant/wpa_supplicant-wlp2s0.conf
network={
	ssid="Labor-WLAN"
	#psk="Werkstatt2026"
	psk=9b8f6fba7006590e7e400d939dfe005db4830a496e54a0b540f6c32c90d356c9
}
```

Die Zeile `#psk=` enthält das Passwort im Klartext und gehört gelöscht, die Datei bekommt die Rechte 600. Dann:

```
sudo wpa_supplicant -B -i wlp2s0 -c /etc/wpa_supplicant/wpa_supplicant-wlp2s0.conf
sudo wpa_cli status                  # wpa_state=COMPLETED heißt verbunden
iw dev wlp2s0 link
sudo dhclient -v wlp2s0              # Adresse, Gateway und DNS per DHCP
```

`-B` schickt den Dienst in den Hintergrund. Auf Debian startet `systemctl enable --now wpa_supplicant@wlp2s0` genau diese Datei bei jedem Start.

Wo **NetworkManager** läuft, übernimmt er das alles selbst (`nmcli device wifi connect Labor-WLAN password …`) und startet wpa_supplicant über D-Bus. Beides gleichzeitig auf derselben Karte geht nicht gut. Darum ist wlp2s0 auf werkstatt in /etc/NetworkManager/conf.d/ als `unmanaged` eingetragen.
</Karte>

## Zwei Standardrouten

<Karte nr={3} titel="Wenn Kabel und Funk gleichzeitig da sind">
`dhclient` trägt die Standardroute ohne Metrik ein, also mit 0. NetworkManager vergibt für Kabel 100 und für WLAN 600. Sind beide da, gewinnt bei gleich langem Präfix die **kleinere Metrik**:

```
default via 192.168.2.1 dev wlp2s0 proto dhcp src 192.168.2.31
default via 192.168.1.1 dev enp0s31f6 proto dhcp src 192.168.1.23 metric 100
```

Damit geht plötzlich der ganze Verkehr über das langsamere WLAN, obwohl das Kabel noch steckt. `ip route get ZIEL` zeigt, welcher Weg gilt. Ändern lässt sich das mit `ip route replace default via 192.168.2.1 dev wlp2s0 metric 700` oder dauerhaft über die Metrik im jeweiligen Werkzeug.
</Karte>
