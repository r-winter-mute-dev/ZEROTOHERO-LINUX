Der alte Laserdrucker ist am Wochenende gegen ein neues Modell getauscht worden. Er hat dieselbe Adresse 192.168.1.40 bekommen, die Kollegen drucken problemlos. Nur von werkstatt aus kommt nichts an, nicht einmal ein Ping. Kabel, Adresse und Route stimmen. **Deine Mission: Finde heraus, warum werkstatt den neuen Drucker nicht erreicht, räum die Nachbartabelle auf und sorg dafür, dass der Fehler beim nächsten Start nicht wiederkommt.** Lernziel 205.1.

## Vom Paket zum Kabel

<Karte nr={1} titel="ARP: Wer hat 192.168.1.40?">
IP-Adressen gelten im ganzen Netz, aber auf dem Ethernet-Kabel zählt die **MAC-Adresse** (48 Bit, etwa `00:1f:29:dd:ee:01`). Bevor werkstatt ein Paket an einen Nachbarn im eigenen Netz schickt, muss es dessen MAC kennen. Das erledigt **ARP** (Address Resolution Protocol, RFC 826):

1. werkstatt fragt per Broadcast: „Wer hat 192.168.1.40? Sag es 192.168.1.23.“
2. Der Drucker antwortet direkt: „192.168.1.40 ist bei 00:1f:29:dd:ee:01.“
3. werkstatt merkt sich die Antwort in der **Nachbartabelle** (ARP-Cache).

Für Ziele in fremden Netzen fragt werkstatt nicht nach dem Ziel, sondern nach der MAC des **Gateways**. Bei IPv6 übernimmt **Neighbor Discovery** (NDP) mit ICMPv6 dieselbe Aufgabe, zu sehen mit `ip -6 neigh`.

Ein **Gratuitous ARP** ist eine Antwort, nach der niemand gefragt hat: Ein Rechner verkündet seine eigene Zuordnung, etwa nach dem Start oder wenn bei einem Ausfall eine andere Maschine eine Adresse übernimmt. Genau diesen Mechanismus nutzen Angreifer beim **ARP-Spoofing**, darum tragen manche Admins wichtige Nachbarn fest ein.
</Karte>

## Die Nachbartabelle

<Karte nr={2} titel="Ansehen, prüfen, ändern">
```
$ ip neigh show
192.168.1.1 dev enp0s31f6 lladdr 9c:c9:eb:12:34:56 router REACHABLE
192.168.1.40 dev enp0s31f6 lladdr 00:1f:29:aa:bb:cc PERMANENT
$ arp -n
Address                  HWtype  HWaddress           Flags Mask            Iface
192.168.1.40             ether   00:1f:29:aa:bb:cc   CM                    enp0s31f6
```

Die Zustände: **REACHABLE** ist frisch bestätigt. **STALE** ist alt, der Eintrag gilt aber weiter und wird beim nächsten Paket über **DELAY** und **PROBE** geprüft. **FAILED** bekam keine Antwort, **INCOMPLETE** wartet gerade auf eine. **PERMANENT** hat jemand fest eingetragen. Dieser Eintrag wird **nie** geprüft und nie ersetzt, auch wenn das Gerät dahinter längst ein anderes ist. In `arp -n` steht dafür das Flag **M**, `C` heißt vollständig.

```
sudo ip neigh del 192.168.1.40 dev enp0s31f6
sudo ip neigh replace 192.168.1.40 lladdr 00:1f:29:dd:ee:01 dev enp0s31f6 nud permanent
sudo ip neigh flush dev enp0s31f6            # alle dynamischen Einträge verwerfen
sudo arp -d 192.168.1.40                     # net-tools
sudo arp -s 192.168.1.40 00:1f:29:dd:ee:01   # fester Eintrag mit net-tools
sudo arp -f /etc/ethers                      # feste Einträge aus einer Datei laden
```

Feste Einträge kennt der Kernel nur bis zum Neustart. Wer sie dauerhaft braucht, legt sie in **/etc/ethers** ab (`MAC ADRESSE` pro Zeile) und lässt sie beim Start mit `arp -f` laden, etwa per systemd-Unit. Das schützt vor Spoofing, wird aber zur Falle, sobald Hardware getauscht wird.
</Karte>
