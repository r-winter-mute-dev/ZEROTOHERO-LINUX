Im Journal von werkstatt tauchen Lesefehler auf /dev/sdb auf. Die SSD ist zwei Jahre alt und trägt das Archiv der Messreihen auf XFS. **Deine Mission: Frag die SSD mit smartctl, wie es ihr geht, lass smartd sie künftig überwachen und sichere das Archiv mit xfsdump, solange es noch geht.** Lernziel 203.2 (XFS und SMART).

## XFS

<Karte nr={1} titel="Werkzeuge für XFS">
XFS ist das Standarddateisystem von Red Hat und für große Dateien und viele parallele Zugriffe gebaut. Verkleinern kann man es nicht, nur vergrößern (`xfs_growfs`).

| Befehl | Wirkung |
|---|---|
| `mkfs.xfs -L archiv /dev/sdb3` | anlegen (`-f` überschreibt ein bestehendes Dateisystem) |
| `xfs_info /srv/archiv` | Aufbau zeigen: Allocation Groups (agcount), Blockgröße, Log |
| `xfs_repair -n /dev/sdb3` | prüfen, **ohne** zu ändern (ausgehängt) |
| `xfs_repair /dev/sdb3` | reparieren (ausgehängt) |
| `xfs_admin -L neu /dev/sdb3` | Label ändern |
| `xfs_db`, `xfs_fsr` | untersuchen, defragmentieren |

`xfs_check` steht noch in den Lernzielen, wurde aber aus den xfsprogs entfernt. Heute prüft man mit `xfs_repair -n`. `fsck.xfs` tut absichtlich nichts, darum steht in der fstab bei XFS als letztes Feld 0.

Zum Sichern hat XFS eigene Programme im Paket **xfsdump**. `xfsdump` sichert ein eingehängtes XFS mit Rechten, erweiterten Attributen und Quotas in eine Datei oder auf Band. Die **Stufe** (`-l`) bestimmt den Umfang: 0 sichert alles, Stufe n sichert, was sich seit der letzten Sicherung mit kleinerer Stufe geändert hat. Über alle Läufe führt xfsdump ein **Inventar**, das `xfsrestore -I` zeigt.

```
xfsdump -l 0 -L voll-2026-11 -M platte -f /backup/archiv-0.dump /srv/archiv
xfsrestore -f /backup/archiv-0.dump -t           # Inhalt zeigen
xfsrestore -f /backup/archiv-0.dump /tmp/zurueck  # zurückspielen
```

`-L` setzt die Bezeichnung der Sitzung, `-M` die des Mediums. Fehlen sie, fragt xfsdump danach.
</Karte>

<Merke>XFS prüfen mit xfs_repair -n, nicht mit fsck oder xfs_check. Sichern mit xfsdump -l 0 -f DATEI QUELLE, zurück mit xfsrestore -f DATEI ZIEL.</Merke>

## SMART

<Karte nr={2} titel="Die Platte selbst fragen">
**SMART** (Self-Monitoring, Analysis and Reporting Technology) ist die Selbstüberwachung in Festplatten und SSDs. Das Paket **smartmontools** bringt zwei Programme mit:

**smartctl** fragt einmalig ab:

| Option | Zeigt |
|---|---|
| `-i` | Modell, Seriennummer, Firmware |
| `-H` | Gesamturteil PASSED oder FAILED |
| `-A` | die Attribute mit Rohwerten |
| `-a` | alles zusammen |
| `-t short` / `-t long` | Selbsttest starten (Minuten bzw. Stunden) |
| `-l selftest` | Ergebnisse der Selbsttests |

Das Gesamturteil schlägt erst sehr spät an. Wichtiger sind die Rohwerte: **Reallocated_Sector_Ct** (schon ersetzte Sektoren), **Current_Pending_Sector** (Sektoren, die sich nicht mehr lesen lassen) und **Offline_Uncorrectable**. Steigen sie, gehören die Daten auf eine andere Platte, auch wenn noch PASSED dasteht.

**smartd** überwacht im Hintergrund nach `/etc/smartd.conf`. Debian liefert eine Zeile mit **DEVICESCAN**, die alle Platten findet und alles Folgende ignoriert. Für einzelne Platten schreibst du eigene Zeilen:

```
/dev/sdb -a -o on -S on -s (S/../.././02|L/../../6/03) -m root
```

`-a` überwacht alles, `-s` plant Selbsttests (kurz jeden Tag um 2 Uhr, lang samstags um 3 Uhr), `-m root` schickt bei Problemen eine Mail an root. Danach `systemctl restart smartd` (Debian: smartmontools.service).
</Karte>
