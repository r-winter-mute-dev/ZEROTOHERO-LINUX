## Die Zone in named.conf

<Karte nr={1} titel="Eine Zone anmelden">
Eine eigene Zone braucht zweierlei: einen Eintrag in der Konfiguration und eine Zonendatei. Auf Debian gehört der Eintrag in `/etc/bind/named.conf.local`:

```
zone "lab.example.org" {
    type primary;
    file "/etc/bind/db.lab.example.org";
};
```

`type primary` heißt: Dieser Server hält die Originaldaten (ältere Schreibweise und in vielen Prüfungsfragen: `type master`). Ein **sekundärer** Server (`type secondary`, früher `slave`) holt sich die Zone per Zonentransfer vom primären. Steht in `file` ein relativer Pfad, gilt er ab `directory` aus den Optionen. Auf Red Hat heißt das: `file "lab.example.org.zone";` liegt in `/var/named/`.

Die Zonendatei gehört root und muss für named lesbar sein. Schreibrechte braucht named nur für Zonen, die er selbst ändert (sekundäre Zonen, dynamische Updates, DNSSEC-Signaturen).
</Karte>

## Die Zonendatei

<Karte nr={2} titel="Aufbau">
```
$TTL 3600
@   IN  SOA ns1.lab.example.org. hostmaster.lab.example.org. (
            2026112701 ; Seriennummer
            7200       ; Refresh
            3600       ; Retry
            1209600    ; Expire
            900 )      ; negative TTL
    IN  NS  ns1.lab.example.org.
    IN  MX  10 mail.lab.example.org.
ns1     IN  A      192.168.1.23
mail    IN  A      192.168.1.25
www     IN  CNAME  werkstatt
```

- **$TTL** legt fest, wie lange andere Server eine Antwort zwischenspeichern dürfen. **$ORIGIN** setzt den Namen, der an Namen ohne Punkt angehängt wird, anfangs der Zonenname. `@` steht für genau diesen Namen. **$INCLUDE** liest eine weitere Datei ein.
- **Der Punkt am Ende** macht einen Namen vollständig. `ns1.lab.example.org` ohne Punkt würde zu `ns1.lab.example.org.lab.example.org.`, ein Klassiker.
- Eine Zeile, die mit Leerraum beginnt, gilt für denselben Namen wie die Zeile davor. NS und MX oben gehören also zu `@`.
- **SOA** (start of authority): primärer Server (MNAME), Mailadresse des Verantwortlichen mit Punkt statt @ (RNAME), dann fünf Zahlen. Die **Seriennummer** muss bei jeder Änderung steigen, üblich ist JJJJMMTTNN. **Refresh**: wie oft sekundäre Server nachsehen. **Retry**: wann sie es nach einem Fehler erneut versuchen. **Expire**: nach welcher Zeit ohne Kontakt sie die Zone aufgeben. Die letzte Zahl ist heute die **negative TTL**, also wie lange ein „gibt es nicht“ gilt.
- Kommentare beginnen mit `;`. Klammern erlauben, einen Eintrag über mehrere Zeilen zu schreiben.
</Karte>

<Karte nr={3} titel="Die Eintragstypen">
| Typ | Inhalt | Beispiel |
|---|---|---|
| A | IPv4-Adresse | `laser IN A 192.168.1.40` |
| AAAA | IPv6-Adresse | `laser IN AAAA 2001:db8:1::40` |
| CNAME | anderer Name (Alias) | `www IN CNAME srv1` |
| MX | Mailserver mit Priorität (kleiner = zuerst) | `@ IN MX 10 mail` |
| NS | zuständiger Nameserver | `@ IN NS ns1` |
| PTR | Name zu einer Adresse (Rückwärtszone) | `40 IN PTR laser.lab.example.org.` |
| TXT | freier Text, etwa SPF | `@ IN TXT "v=spf1 mx -all"` |
| SRV | Dienst mit Priorität, Gewicht, Port, Ziel | `_ldap._tcp IN SRV 0 0 389 srv1` |

Regeln, die named-checkzone durchsetzt: Ein **CNAME** steht allein, neben ihm darf derselbe Name keine anderen Einträge haben. Darum hat auch `@` nie einen CNAME. Ziele von MX und NS sollen keine Aliasse sein. Jeder Name in einem NS-Eintrag innerhalb der Zone braucht eine Adresse.
</Karte>
