## Den laufenden Server steuern

<Karte nr={1} titel="rndc">
**rndc** (remote name daemon control) spricht über TCP-Port **953** mit named. Beide kennen denselben geheimen Schlüssel: auf Debian `/etc/bind/rndc.key`, auf Red Hat `/etc/rndc.key`, angelegt bei der Installation (sonst mit `rndc-confgen -a`). Die Datei darf nur root und der Benutzer von named lesen, darum läuft rndc mit sudo.

```
sudo rndc status              # läuft er? wie viele Zonen? Abfrage-Log an?
sudo rndc reload              # Konfiguration und geänderte Zonen neu laden
sudo rndc reload lab.example.org   # nur diese Zone
sudo rndc reconfig            # Konfiguration und nur neue Zonen
sudo rndc flush               # Cache leeren
sudo rndc dumpdb -cache       # Cache nach named_dump.db schreiben
sudo rndc querylog on         # jede Anfrage protokollieren
sudo rndc stop                # beenden
```

Ältere Werkzeuge sprechen named über **Signale** an: `kill -HUP` lässt ihn neu laden wie `rndc reload`, `kill -TERM` beendet ihn sauber. Die PID liefert `pidof named` oder `systemctl status named`. `systemctl reload named` ruft auf Debian intern `rndc reload` auf.
</Karte>

## Protokolle

<Karte nr={2} titel="Der logging-Block">
Ohne eigene Einstellungen schreibt named über syslog ins Journal: `journalctl -u named`. Mit einem **logging**-Block lenkt man einzelne **Kategorien** in eigene **Kanäle**:

```
logging {
    channel abfragen {
        file "/var/log/named/abfragen.log" versions 3 size 5m;
        severity info;
        print-time yes;
    };
    category queries { abfragen; };
};
```

Ein **channel** ist ein Ziel: eine Datei (mit `versions` und `size` dreht named sie selbst weiter), `syslog`, `stderr` oder `null`. Eine **category** ist eine Art von Meldung, etwa `queries` für jede Anfrage, `xfer-out` für Zonentransfers, `security` oder `default` für alles ohne eigene Zuordnung.

Zwei Fallen: Der Ordner muss existieren und für den Benutzer von named schreibbar sein, sonst startet named nicht („configuring logging: file not found“). Und eine Kategorie `queries` schaltet das Abfrageprotokoll ein. `rndc querylog off` schaltet es im Betrieb wieder ab, ohne die Datei zu ändern. Auf einem gut besuchten Server wächst das Protokoll schnell.
</Karte>

<Merke>rndc steuert named über Port 953 mit einem Schlüssel, darum mit sudo. kill -HUP lädt neu wie rndc reload. Eigene Protokolle mit logging, channel und category, der Ordner muss für named schreibbar sein.</Merke>
