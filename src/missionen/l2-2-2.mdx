Der Quellcode von 6.18.65 liegt in /usr/src/linux. Jetzt soll daraus ein Kernel werden, der auf messpc genauso gut läuft wie der von Debian, sich aber als eigener Bau zu erkennen gibt. **Deine Mission: Konfiguriere den Kernel auf Grundlage der Debian-Konfiguration, ändere gezielt einzelne Optionen und baue Kernel und Module.** Lernziel 201.2.

## Was zum Bauen gebraucht wird

<Karte nr={1} titel="Werkzeuge und die Datei .config">
Zum Bauen brauchst du einen C-Compiler und make (Paket **build-essential**), dazu **flex** und **bison** für die Konfigurationsprogramme, **bc** für Berechnungen beim Bau, **libelf-dev** und **libssl-dev** für Objekt-Werkzeuge und Signaturen, **libncurses-dev** für menuconfig. Debian-Konfigurationen schalten Typinformationen (BTF) ein, dafür braucht es **pahole** aus dem Paket **dwarves**. Auf Red Hat heißen die Pakete ähnlich mit `-devel` am Ende.

Welche Teile in den Kernel kommen, steht in der Datei **.config** im Quellbaum. Jede Option ist ein Symbol mit einem Wert:

```
CONFIG_E1000E=m              als Modul
CONFIG_BLK_DEV_INITRD=y      fest eingebaut
# CONFIG_BLK_DEV_FD is not set   gar nicht
CONFIG_LOCALVERSION="-lab"   ein Text
```

Die bequemste Grundlage ist die Konfiguration des laufenden Kernels: `cp /boot/config-$(uname -r) .config`. Manche Kernel tragen ihre Konfiguration auch in sich, dann liegt sie unter `/proc/config.gz` (Option IKCONFIG_PROC).
</Karte>

## Die Ziele von make

<Karte nr={2} titel="Konfigurieren">
Alle Ziele zeigt `make help`. Fürs Konfigurieren gibt es mehrere Wege:

| Ziel | Was es tut |
|---|---|
| `make config` | fragt jede Option einzeln ab, Zeile für Zeile |
| `make menuconfig` | Menü im Terminal (ncurses). `nconfig` ist eine neuere Fassung. |
| `make xconfig`, `make gconfig` | grafisch mit Qt bzw. GTK |
| `make oldconfig` | übernimmt die vorhandene .config und fragt nur nach **neuen** Optionen |
| `make olddefconfig` | wie oldconfig, setzt neue Optionen aber still auf ihre Vorgabe |
| `make defconfig` | neue .config aus den Vorgaben der Architektur |
| `make localmodconfig` | schaltet alle Module ab, die gerade nicht geladen sind. Ergibt einen kleinen Kernel, der genau auf diesen Rechner passt. |

Einzelne Optionen ändert **scripts/config** ohne Menü: `scripts/config --enable IKCONFIG`, `--disable`, `--module`, `--set-str LOCALVERSION "-lab"`, `--state` zum Nachsehen. Danach `make olddefconfig`, damit abhängige Optionen stimmen.

**LOCALVERSION** hängt einen Text an die Version. Aus 6.18.65 wird 6.18.65-lab, und genau so heißen später `/boot/vmlinuz-6.18.65-lab` und `/lib/modules/6.18.65-lab/`. Wer das vergisst, überschreibt beim Installieren womöglich einen anderen Kernel gleicher Version. `make kernelrelease` zeigt, wie der Kernel heißen wird.
</Karte>

<Karte nr={3} titel="Bauen und aufräumen">
`make` ohne Ziel (gleichbedeutend mit `make all`) baut den Kernel und alle Module. Mit **-j** arbeitet make mehrere Aufgaben gleichzeitig ab, üblich ist `make -j$(nproc)`. Einzeln gehen `make bzImage` und `make modules`. Je nach Konfiguration dauert das einige Minuten bis über eine Stunde. Ein Kernel aus der vollen Debian-Konfiguration baut Tausende Module, einer nach `localmodconfig` nur einige Dutzend.

Danach liegen im Baum `vmlinux`, `System.map`, das gepackte Abbild **arch/x86/boot/bzImage** und die Module (`*.ko`). Die Zeile vor `BUILD arch/x86/boot/bzImage` zeigt das Packverfahren, etwa `XZKERN` oder `ZSTD22`. Gewählt wird es unter General setup → Kernel compression mode: gzip, bzip2, lzma, xz, lzo, lz4 oder zstd. Das initramfs packt Debian getrennt davon, eingestellt mit `COMPRESS=` in `/etc/initramfs-tools/initramfs.conf`.

Aufräumen: `make clean` löscht das Erzeugte, behält aber die .config. `make mrproper` löscht auch die .config, `make distclean` zusätzlich Sicherungs- und Patch-Reste. Sichere die .config, bevor du mrproper aufrufst.

Eine Falle mit der Debian-Konfiguration: Sie verlangt in `CONFIG_SYSTEM_TRUSTED_KEYS` eine Schlüsseldatei, die es nur im Quellpaket von Debian gibt. Der Bau bricht dann mit „Keine Regel vorhanden, um das Ziel „debian/certs/…“ … zu erstellen“ ab. Abhilfe: `scripts/config --disable SYSTEM_TRUSTED_KEYS` (oder mit `--set-str` leeren).
</Karte>

<Merke>make -j$(nproc) baut alles. Ergebnis: arch/x86/boot/bzImage und die Module. clean behält .config, mrproper nicht. Debian-Konfiguration: SYSTEM_TRUSTED_KEYS leeren.</Merke>

<Hinweis titel="Wenn etwas fehlt">
Fehlt ein Werkzeug, bricht make mit Meldungen wie `flex: not found` oder `openssl/opensslv.h: No such file or directory` ab. Der Paketname steckt meist in der Meldung. Beim echten Bau lohnt `make -j$(nproc) 2>&1 | tee bau.log`: Die erste Fehlermeldung steht weit oben, nicht am Ende.
</Hinweis>
