## Vom Download zum Quellbaum

<Karte nr={1} titel="Tarballs prüfen und auspacken">
Quellcode kommt fast immer als **Tarball**: ein tar-Archiv, das zusätzlich gepackt ist. Die Endung verrät den Packer:

| Endung | Packer | tar-Option |
|---|---|---|
| `.tar.gz`, `.tgz` | gzip | `z` |
| `.tar.bz2`, `.tbz2` | bzip2 | `j` |
| `.tar.xz`, `.txz` | xz | `J` |

```
sha256sum -c lagerist-2.4.1.tar.gz.sha256    # Prüfsumme stimmt?
tar tzf lagerist-2.4.1.tar.gz | head          # erst ansehen
tar xzf lagerist-2.4.1.tar.gz -C ~/quellen    # dann auspacken
xz -dc paket.tar.xz | tar xf -                # dasselbe in zwei Schritten
```

Beim Auspacken erkennt GNU tar die Kompression auch ohne `z`, `j` oder `J`. Vor dem Auspacken lohnt `tar t`: Ein sauberer Tarball legt alles in **einen** Ordner wie `lagerist-2.4.1/`. Erst prüfen, dann vertrauen: `sha256sum -c` gegen die veröffentlichte Prüfsumme, besser noch `gpg --verify` gegen eine Signatur (Lernziel 110.3).

Wohin damit? Die Verzeichnisstruktur (FHS) sieht **/usr/src** für Quellcode vor, dort liegen etwa Kernelquellen und die Header für Module (Akt 2). Für eigene Quellen gibt es **/usr/local/src**. Gebaut wird trotzdem als normaler Benutzer, darum hier `~/quellen`.
</Karte>

## configure, make, make install

<Karte nr={2} titel="Der Dreischritt der GNU-Werkzeuge">
Die meisten C-Programme nutzen **GNU Autoconf** und **Automake**. Das Ergebnis ist ein Skript `configure` im Quellbaum. Erst einmal `README` und `INSTALL` lesen, dann:

1. **`./configure`** prüft das System: Gibt es einen Compiler? Welche Bibliotheken? Danach schreibt es das **Makefile** und `config.h`. Optionen passen den Bau an: `--prefix=/opt/lagerist` legt das Ziel fest (Standard **/usr/local**), `--sysconfdir=/etc` den Ort der Konfiguration, `--without-tui` oder `--disable-nls` schalten Teile ab. Alle Optionen zeigt `./configure --help`. Was schiefging, steht in **config.log**.
2. **`make`** liest das Makefile und übersetzt. Es baut nur neu, was sich seit dem letzten Lauf geändert hat. `make -j$(nproc)` nutzt alle Kerne.
3. **`make check`** (manchmal `make test`) führt die mitgelieferten Tests aus.
4. **`sudo make install`** kopiert Programm, Handbuchseite und Konfiguration unter das Präfix.

Neuere Projekte nutzen statt Autoconf auch CMake oder Meson. Die Idee bleibt gleich: konfigurieren, bauen, installieren.
</Karte>

## Wenn configure scheitert

<Karte nr={3} titel="Fehlende Werkzeuge und Bibliotheken">
Ein frisches Debian hat weder `gcc` noch `make`. configure bricht dann früh ab:

```
checking for gcc... no
configure: error: no acceptable C compiler found in $PATH
```

Das Metapaket **build-essential** bringt gcc, make und die Header der C-Bibliothek mit. Auf Red Hat heißt das Gegenstück `dnf group install "Development Tools"`.

Die zweite typische Meldung betrifft Bibliotheken. Die Bibliothek zum **Ausführen** (etwa `libncursesw6`) ist oft schon installiert, zum **Bauen** braucht es aber die Header und Verweise aus dem Entwicklerpaket: auf Debian mit der Endung **-dev** (`libncurses-dev`), auf Red Hat **-devel** (`ncurses-devel`). Alternativ schaltet man den Teil ab, wenn das Programm es anbietet, etwa mit `--without-tui`.

Steht in der Meldung nicht genug, hilft **config.log**: Dort stehen der genaue Testaufruf und die Antwort des Compilers.
</Karte>

<Karte nr={4} titel="Was make install anrichtet">
Nach `make install` liegen die Dateien verteilt unter dem Präfix: `/usr/local/bin/lagerist`, `/usr/local/etc/lagerist.conf`, `/usr/local/share/man/man1/lagerist.1`. Kein Paketmanager weiß davon. `dpkg -S` findet die Dateien nicht, und ein Update von Debian fasst sie nicht an.

Weil `/usr/local/bin` im PATH **vor** `/usr/bin` steht, gewinnt die selbst gebaute Version, falls Debian später ein gleichnamiges Paket installiert. Bash merkt sich gefundene Pfade. Nach einer neuen Installation hilft `hash -r`, wenn die Shell noch das alte Programm startet. `type -a lagerist` zeigt alle Fundstellen.

Vor dem Herunterladen fertiger Programme hilft **uname**: `uname -m` nennt die Architektur (`x86_64`, `aarch64`), `uname -r` den Kernel, für den Module gebaut werden müssen.
</Karte>
